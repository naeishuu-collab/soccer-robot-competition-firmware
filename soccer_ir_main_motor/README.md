# サッカーロボット（カメラなし）

このワークスペースは **MAIN・IR・MOTORの3基板だけ**でAUTO IR追跡を動かす構成です。カメラ基板・LINE基板は接続も書き込みも不要です。MAIN・IR・MOTORはこのフォルダー内の同じ版をそれぞれの基板へ書き込んでください。

添付 chase (2).zip は方位・MOTOR配列・車輪軸角の資料として使っています。ZIP側とこのプロジェクトではRS485通信形式が異なるため、ZIPのMAIN/IR/MOTORを混ぜて書き込まないでください。

## ZIPの資料を反映した点

- IRのセンサー番号は反時計回り、送信方位は「前0°・右90°・後180°・左270°」にそろえました。GPIO18/21/24/27をそれぞれ前/左/後/右として扱います。
- MOTOR配列順は [M4=RR, M1=LF, M2=RF, M3=LR] = [RR, LF, RF, LR]。IN1=[6,12,11,9]、IN2=[7,13,10,8]をMAIN・MOTORの両方に反映し、コンパイル時static_assertで固定しています。
- ZIPの車輪軸角[45,225,315,135]（前0°・右90°）をMotion座標[x=右,y=前]の[45,225,135,315]へ変換。車輪計算の符号は[+1,+1,+1,+1]、MOTORの電気出力極性は直近の指示どおりRRのみ反転[-1,+1,+1,+1]です。両設定は別レイヤーです。
- 車輪軸角と運動学テーブルはZIP由来の候補値で、実車の進行方向は未確認です。加速度ログは車輪方向やyaw符号の根拠にしません。`kMotorWheelConfigConfigured=false` と `kCompetitionArmed=false` を維持し、競技AUTOを無効にしています。

## ビルドと確認

Arduino CLI と Raspberry Pi Pico/RP2040 Arduino core が必要です。`サッカーロボット_カメラなし.code-workspace`を開き、既定ビルド（Ctrl+Shift+B）を実行するとMAIN・IR・MOTORだけを順番にコンパイルします。各基板はタスク一覧から個別にもコンパイルできます。

各スケッチはそれぞれのフォルダー内で完結してビルドできます。IRの校正用ヘッダー（`ir_low_window.h`、`ir_match.h`、`ir_profile.h`）も`ir/`に含めています。`common/src/`は共通コードの参照用で、ビルド時には各`.ino`内のコピーが使われます。

## IRセンサー個体差の校正

ZIPの10 cm・12方向キャリブレーションをIR方位推定に適用しました。照合が十分確かなときは30度区分の校正角を使い、それ以外は従来の連続ベクトル推定へ戻ります。10 cm以外は未検証です。追加データ取得と適用範囲は[IR校正手順](docs/IR_CALIBRATION_TSSP58038_JA.md)を参照してください。シリアルモニターの `CAL START` はCSVログ取得用です。

## 実機での確認

- コードのコンパイル成功だけでは、実際の進行方向、モーター極性、RS485配線は確定しません。現時点では「コードが起動した」までで、「正しい方向に動いた」確認は未完了として扱います。
- 起動時に自動で `AUTO IR` を選択し、ボールとBNO headingが新鮮になった瞬間に自動ARMします。`AUTO IR` / `ARM IR` コマンドは不要です（互換のため残しています）。診断表示がOFFでも起動メッセージは表示します。ARM時のBNO headingを姿勢目標に取り、IRまたはBNOが失われると停止してDISARMしますが、復帰後は自動で再ARMします。停止には `S` または電源スイッチを使います。**電源投入直後から勝手に動き出すため、必ず車輪を浮かせて試験してください。**
- IR試験のPWM上限は210/255、非ゼロ指令の下限は120/255です。下限はモーター始動用で、実車速度を保証しません。`kIrTestWheelMappingVerified=false` と `kBnoHeadingTurnSign=0` は未検証のまま維持します。この状態でも車輪を浮かせた `AUTO IR` 試験はできますが、BNO旋回補正はOFFです。車輪配置の確認まで、床上で走らせないでください。
- AUTO IRは、操作者が停止手段を保持する車輪浮かせ試験専用です。ファームウェアは車輪が浮いているか検知できません。競技場での無監督走行は行わないでください。競技用AUTO FLOOR/FLOATは車輪設定・安全入力・境界検知の確認が終わるまで無効です。
- MAIN→MOTOR確認は車輪を浮かせ、キッカーを無効にして、MAINのシリアルモニター（115200bps）で `M 128 0 0 0`（RR）、`M 0 128 0 0`（LF）、`M 0 0 128 0`（RF）、`M 0 0 0 128`（LR）を一つずつ入力し、各車輪とINピンを照合します。各M指令は300msで自動停止し、`S`は即時停止指令を送ります。RRは出力極性-1のため正指令でIN2側が駆動し、他の3輪はIN1側です。
- MOTOR基板のシリアル診断で output_ready=1 と command_active=1 を確認します。RS485_rx が0のままならMAIN/MOTOR間の配線・DE・トランシーバーを確認し、受信が増えても command_active が0ならフレーム形式または破棄カウンターを確認してください。command_active=1で出力がない場合は、MOTORドライバーのVM電源、GND、IN端子からドライバーまでを確認します。
- 方向を確認するまでは競技用AUTOを有効にしないでください。カメラもLINE境界検知もないため、フィールド端で自動停止できません。MAIN→MOTORは12バイトの4輪PWMフレーム（0xAA、4値、XOR、0x55）でそろえています。旧ZIPの移動ベクトル形式と現行版を混ぜないでください。
- BNOのyaw符号を調べるには、`DIAG ON` の `heading_rel_deg` を見ながら機体を手で左右に回します。車輪を浮かせて各輪の正逆と、4輪同時の旋回方向も確認してください。加速度ログの前後左右軸をyaw符号や車輪符号へ流用しません。
- IR近接キックしきい値 kIrKickCloseSignal は0のままです。測定と安全確認なしにキック条件を有効化しないでください。

## スケッチ

| フォルダー | 基板 | 用途 |
|---|---|---|
| main/ | MAIN (RP2350B) | AUTO IR・走行制御 |
| ir/ | IR (RP2350A) | 赤外線ボール方位・校正プロファイル |
| motor/ | MOTOR (RP2350A) | 4輪モータードライバー |

このワークスペースでは上記3フォルダーだけを表示・ビルド対象にします。リポジトリ内のLINE・テスト・設定フォルダーはこの3基板の起動に使いません。

## MAIN の BNO055 診断

MAINのUSBシリアル出力は通常オフです。`BNO LOG START` / `BNO LOG STOP` は記録状態だけを変更し、応答を出しません。`BNO LOG DUMP` を送ると保持したBNO CSVを出力します。診断表示が必要なときだけ `DIAG ON` で定期診断とコマンド応答を有効にし、`DIAG OFF` で停止します。診断表示は電源再投入でオフに戻ります。これらの設定はUSBシリアル出力だけに作用し、通信・センサー取得・安全制御には影響しません。

`main/main.ino` は従来どおり IMUPLUS モードを使います。`DIAG BNO` の `heading_rel_deg` は起動時基準の相対方位、`roll_pitch_deg(R/P)` は roll・pitch（度）、`linaccel_mps2_sensorXYZ` は `VECTOR_LINEARACCEL` の X/Y/Z（m/s²）、`cal(S/G/A/M)` はシステム・ジャイロ・加速度・磁力計の校正値（各0〜3）です。IMUPLUSでは磁力計を融合に使わないため、M=0だけで異常とは判断しません。

`read=OK/WAIT/FAIL` は完全な読取成功・起動安定待ち・読取失敗を示します。`updates/fail` はMAIN側の完全なI²C読取回数と失敗回数、`age_ms` は最後に成功したMAIN側読取からの経過時間です（未取得時は `none`）。20 msごとに読み取りますが、この時刻はBNO055内部のフュージョン更新時刻ではありません。

座標はBNO055のセンサー軸です。このスケッチでは軸の再マッピングをしていません。X/Y/Zが機体の前後・左右・上下のどれに当たるか、符号も含めて、実際のモジュールの軸表示と取り付け向きを確認してください。車輪を浮かせた状態で向きを変え、各軸の符号を実測してから機体座標に対応付けます。

線形加速度はフュージョンで重力成分を差し引いた値です。静止時は概ね0 m/s²になりますが、傾き推定・校正・ノイズによる残差はありえます。一定速度で進んでいる間は加速度がほぼ0となり、速度は分かりません。加速度を積分して速度を求める方法も誤差が急速に蓄積します。したがって、この診断値による自動操舵・速度推定は有効化していません。

### MAINの線形加速度ログ

MAINのUSBシリアル（115200bps）で次のコマンドを1行ずつ送ります。

- `BNO LOG START`：記録を開始し、前のログを消去します。
- `BNO LOG STOP`：記録を止め、RAM上のログを保持します。
- `BNO LOG DUMP`：記録を止め、保持したログをCSVで出力します。
- `DIAG ON` / `DIAG OFF`：任意の定期診断表示を切り替えます。起動時はオフです。

ログは512サンプルのRAMリングバッファ（約8KiB）です。MAINの既存BNO055読取周期20msを使うため目標は約50Hzで、取得済みの成功サンプルだけを保存します。追加のI²C読取は行いません。512件を超えると古い行から上書きし、上書き数をCSV先頭のコメント行に表示します。ダンプ中は診断テキストを一時停止し、シリアル送信可能量を見ながら少しずつ出力します。

CSVは`timestamp_us,ax_sensor_mps2,ay_sensor_mps2,az_sensor_mps2`列です。シリアル保存から使う場合は、このヘッダー行から数値行を取り出し、`#`コメントと前後の状態メッセージを除いてください。時刻は記録開始後、MAINが各I²C読取を完了した時点の`micros()`値です（約71.6分で32bit周回）。行間隔から実測周期を確認してください。サンプルはセンサー座標系のXYZで、機体座標へ変換していません。

ロガーは加速度を制御に使いません。起動時は常に停止し、AUTO IRは `AUTO IR` と `ARM IR` の両方を必要とします。BNOログコマンドは既存のRS485・モーター・姿勢制御を変更しません。
