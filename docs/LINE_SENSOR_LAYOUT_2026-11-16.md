# LINEセンサー配置・故障マスク記録

更新日: 2026-11-16

## 根拠と限界

- センサー番号0が機体前方で、番号が時計回りに増え、配置は不等間隔です。これはユーザー提供情報です。
- GP2〜GP25は現在の`line/line.ino`に存在した番号順の配列を`BoardConfig.h`へ移したものです。実基板との導通対応は未測定です。
- 添付`soccer.zip`（SHA-256 `D39977E63DE3C7CAC23FECA27BC9AF064628A34A17E64C260859601AC081DE4A`）には`soccer/line2/line2.kicad_pcb`が含まれます。Q1〜Q24の配置座標から、基板中心(100,100)、基板上方向0°、時計回りで算出した角度はコードの角度表と1°丸めで一致します。
- `soccer/line2/jlcpcb/production_files/BOM-line2.csv`にはRP2354B (U1)、MAX3485 (U14)、SFH309 (Q1〜Q24)があります。ただしBOMのZIP内更新日時は2026-08-25、PCBは2026-11-07です。BOMとPCBの対応リビジョン、現物との一致は確認できません。
- この照合で確認できたのは、そのZIP内のPCB設計におけるQ1〜Q24の相対配置です。ZIP内ファイルが現物基板と同じリビジョンか、Q番号とソフト入力番号0〜23が同じ順序か、基板上方向が機体前方とどう対応するかは未確認です。
- 健全/故障の判定はユーザーの白線上テスト結果です。極性・入力閾値・応答時間は未確認です。

## コードに保持する基板角度候補

`kLineBoardAngleCdeg`にはPCBのQ1〜Q24順に `11, 21, 41, 51, 71, 81, 101, 111, 131, 141, 161, 171, 191, 201, 221, 231, 251, 261, 281, 291, 311, 321, 341, 351` 度を保持します。これは添付PCBの座標から算出した基板内の設計角度で、1°単位に丸めています。Q番号とソフト入力番号0〜23の対応、および機体前方基準へ変換するオフセットは未確定です。

`kLineFrontOffsetConfigured=false`、`kLineAnglesConfigured=false`、`kLinePolarityConfigured=false`のままです。ホストテストコードには候補角度のセンチ度変換と回避演算を検査する項目がありますが、ホストテスト自体は未実行です。仮に実行しても、実機の角度・極性を検証した扱いにはしません。MOTORと競技ARMも無効です。

## 現在の制御設定

- 使用許可18個のビットマスクは`0x00DFF4DD`です。故障マスクは`0x00200B22`です。
- 故障ビットはLINE側のデバウンス入力・検出数・方向ベクトル・送信データから除き、MAINも同じマスクでパケットを検証します。故障ビットを含むLINEパケットは拒否します。LINE基板のUSB診断では全GPIOの生レベルを引き続き表示します。
- 方向推定は各センサーの個別角度を使う非均等配置対応のベクトル合成です。基板角度候補はコードとホストテストにありますが、実機前方オフセットが未確認のため現在は有効角度表が無効です。検出しても回避方向を推測しません。方向不明/曖昧なら移動量0、安全側へ停止します。
- MAINは検出をボール追跡より優先し、ライン解消を200ms確認してから通常制御へ戻ります。LINEデータが100msより古い場合、MAIN制御はFAULTになります。
- デバウンス関数はありますが、極性・センサー応答時間の計測前なので実機設定は無効です。機体の全センサー応答と入力回路を確認するまで競技ARMも無効です。

## テーブル確定に必要な計測

1. 現物基板リビジョンを記録し、番号とGPIOの導通を1〜23番まで確認する。
2. 白/黒面で各センサーと入力回路のレベル、閾値、反応/解除時間を記録する。
3. 機体中心・前方の基準を決め、各白いセンサー素子中心の(x,y)を測る。
4. `atan2(x,y)`相当から前方基準・時計回り正の角度を算出し、実測ログで確認する。
5. 角度表・極性・デバウンスを個別設定し、故障6入力が検出・方向・通信から除外された状態をホスト試験と低速実機試験で確認する。
