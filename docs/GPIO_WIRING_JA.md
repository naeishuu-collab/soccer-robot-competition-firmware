# GPIO・通信の現状と未確認点

利用可能な設計資料とソフトウェア設定を区別する。表のGPIOは設計資料上の値で、実装基板やハーネスの導通確認ではない。

## 情報分類

- MAIN・IR・LINE: プロジェクト配列/設計情報と今回のユーザー報告を分けて記録。基板間ハーネスやすべてのGPIO導通を本作業で再測定していない。
- MOTOR: 今回ユーザー報告の4チャンネルPWM配線はコードへ反映。MOTOR側RS485ピン、安全入力、電源/遮断はUNKNOWN。旧KiCadは [MOTOR_REVISION_DIFF_JA.md](MOTOR_REVISION_DIFF_JA.md) のLEGACY_REFERENCE欄だけで扱う。
- 基板間RS485ハーネス、終端・バイアス: UNKNOWN。

## 現行ソフト設定と設計資料

| 基板 | 設計上の候補 | コードでの状態 | 実機確認 |
|---|---|---|---|
| MAIN | RS485。BNO055 I2C SDA/SCL=GP4/GP5 | I2Cピンを設定。PIO UART不使用。校正オフセット未適用 | BNO055基本動作はユーザー確認。校正精度/ハーネスは未確認 |
| IR | UART TX/RX/DE=GP0/GP1/GP2。12入力=GP18〜29 | 12センサー、0番前方、30°刻み。旧6 byte応答を保持 | 全12入力の方向検知はユーザー確認 |
| LINE | UART候補GP0/GP1、DE=GP27。既存コード入力候補GP2〜25 | 18個有効/6個をマスク。極性/角度未設定、デバウンス無効 | 故障番号と向きはユーザー報告。GPIO導通/角度は未確認 |
| MOTOR新版 | 左前J2=GP13/12、右前J6=GP11/10、左後J7=GP9/8、右後J1=GP7/6 | PWMピン表/マスクを登録。GPIO数=0、TX/RX/DE=-1、`kMotorHardwareConfigured=false`でUART/PWM出力無効 | 各モーター個別回転とMAIN-MOTOR RS485はユーザー報告。4輪合成/極性/停止は未確認 |

バス構成の論理:
MAIN → IR（実配線を照合）
MAIN → LINE（実配線を照合）
MAIN → MOTOR（通信成功はユーザー報告、端子/ポートは不明）
MAIN ↔ BNO055候補 I2C GP4/GP5

ソフトウェアはMAINからIR/LINEを順次要求し、MOTOR形式の指令も組み立てる。ユーザーからMAIN-MOTOR通信テスト成功の報告があるが、今回のCodex検証では再現していない。MOTOR側ピン設定は不明なため、現在のファームウェアでUARTを初期化しない。

## 競技動作に進む前に必要な測定

1. 基板の型番・リビジョン、MCU刻印、端子番号と信号名を記録する。
2. 電源OFFでUART、DE、A/B/GND、終端、各電源レールを導通・短絡確認する。
3. MAIN/IR/LINE候補GPIOを資料と導通測定で確認する。
4. MOTOR報告GPIO表を製造図面・導通測定で照合し、MOTOR側RS485と安全入力の端子/極性も確定する。旧版の番号を代用しない。
5. キッカー回路の充電禁止・残留電荷放電・定格を確認する。
6. センサー極性、物理角度、校正データを記録してから設定を有効化する。

MOTOR旧版の個別ピンや電源表記は現行配線表に転記しない.
