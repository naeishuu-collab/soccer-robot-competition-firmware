# competition コード全体解説

更新日: 2026-11-15  
対象: `competition` 内の現行ソース、設定、テスト用コード。仕様と設定値はコードから読み取れる範囲で説明しています。実機での配線、センサー極性、車輪出力、停止回路の動作を保証するものではありません。

## 全体像

図はソフトウェアの論理構成を示します。特に製造MOTOR新版との配線/通信経路は資料不足でUNKNOWNです。4枚の基板でボール検出、ライン検出、判断、駆動を分担する構想です。MAINがRS485共有バスのマスターとしてIRに要求し、LINEを照会し、MOTORへ指令を送ります。MAINはBNO055の方位も読み、共通制御ロジックで状態と運動指令を決めます。

```text
IR (12センサー) ─┐
LINE (24入力) ────┼─ RS485共有バス ─ MAIN ── RS485指令 ─ MOTOR (4輪)
BNO055 ──────────┘     I2C
```

この図と説明はソフトウェアの論理構成です。MAIN/IR/LINEの候補配線と実装基板の一致、MOTOR新版の物理通信経路は未確認です。

各基板の `.ino` はそれぞれ別のArduinoスケッチです。`common/src` はそれらで共有するプロトコル、通信、安全設定、制御ロジックを置きます。論理上はMAINの要求にIR/LINEが応答し、MOTOR形式の指令を送ります。製造MOTOR新版の受信経路はUNKNOWNです。

## スケッチ

### `main/main.ino` — センサー統合とロボット判断

- IR/LINE向け要求処理とMOTOR形式指令生成を行います。MOTOR新版のUART/DE/バス配線はUNKNOWNで、現物への到達は未確認です。
- BNO055をI2Cで読み、IR・LINE・方位データの鮮度を管理します。周期処理で `MainController.step()` を呼び、停止、待機、ボール探索、ボール接近、ライン回避、FAULT のいずれかを決めます。
- BNO055はGPIO4/5、I2Cアドレス0x28、IMUPLUSで動かします。外部水晶を設定し、旧オフセット値はkBnoOffsetsVerified=falseのため適用せず、500msの安定待ち後に最初の方位を相対角の基準にします。
- 30度を超える単発変化は一旦保留します。同じ値の再確認または同方向・近い角速度の連続サンプルがあれば実際の回転として扱い、方位を1回あたり最大30度ずつ追従させます。SYS校正値3と有限な角度を満たすまで、方位は制御に有効化しません。
- LINE応答の照合、モーター指令送信、診断ログも担当します。BNO初期化は1秒ごとに再試行し、安定待ちは他の処理を止めません。
- 現在は `kDiagnosticMode=true`、モーター指令も無効です。定数の周期値は設定値であり、実機での制御周期測定値ではありません。

### `ir/ir.ino` — ボール方向センサー

- TSSP58038を12個読み、検出数の履歴からセンサーごとの相対的な受信強度を計算します。
- センサー配置の正弦・余弦表で方向を求め、外れ値を抑える履歴フィルターと短時間の方向予測を適用します。
- MAINの1byte要求に既存6byte形式で応答します。方向欄は短時間予測bearing、DIST欄は相対信号で、物理距離ではありません。コヒーレンス/鮮度は診断ログに出し、6byteプロトコルには載せません。
- `SharedBusIrRequestParser` で、共有バス上のCRCフレーム内に偶然現れる `0x01` とIR要求を区別します。

### `line/line.ino` — フィールド境界センサー

- GPIO2〜25の24入力を20ms間隔で読み、生のHIGH/LOWを24bit値として保持します。
- MAINからCRC付きLINE要求を受けた時だけ、検出状態・方向情報を含むCRC付き応答を返します。無要求の周期送信はしません。
- 周期的に生レベル、検出数、方向の有効性、極性設定、サンプル時間、RS485診断値をUSBシリアルへ出します。
- 故障1,5,8,9,11,21番はLINE・MAINの双方でマスクし、残る18個だけを検出数/方向計算に使います。現在は検出極性と実角度が未設定です。角度を推測せず、方向不明時は移動停止になります。

### `motor/motor.ino` — 指令検証と4輪出力

- スケッチには最大64byteずつ受信してフレーム形式、CRC、連番、値域を検査する経路があります。現行MOTORピンが未設定のためUART未初期化で、この経路は製造新版では動作確認していません。MOTOR指令が100msに達した時点での期限切れ・不正フレーム・連番エラーはFAULTにラッチし、物理clearと新しいARM操作まで再開しません。期限切れは受信前にも判定するため、期限後に届いたフレームがタイムアウトを隠しません。
- ソフトウェアモデルは5ms周期で指令鮮度、MAIN enable、E-stop、物理ARMを確認します。4輪速度は正規化し、加減速を制限します。反転・再始動・モード変更ではLOW/LOWを200ms保持します。
- ユーザー報告のTB67H450FNG×4の4組GPIO（J2=13/12、J6=11/10、J7=9/8、J1=7/6）、車輪半径30mm/中心距離94.762mm、20kHz/255/Duty上限128を記録しました。TX/RX/DE=-1、GPIO数0、車輪方向・極性・安全入力未設定、ハードウェア設定falseのため出力しません。
- TB67H450FNGのメーカー資料で4モード表と20kHz範囲を確認しました。実搭載品の接尾辞、波形、出力段の定格は未確認で、ソフトの200ms待機は実機の電気的デッドタイム検証の代わりにはなりません。
- 製造新版のARM/E-stop/clear GPIO・極性・バイアスはUNKNOWNで未割当てです。MOTORのUART初期化とPWM初期化は未確認ピン設定により行いません。MAINも安全入力が確認されるまで診断モード/ARM禁止です。

## 共通コード (`common/src`)

### `RobotProtocol.h` — 通信フレーム

フレーム境界、バージョン、メッセージ種別、最大長、CRC16を定義します。`encodePacket` と `PacketParser` はフレームの生成と分割受信を処理し、部分フレームのタイムアウトや形式・CRCエラーを記録します。`SequenceTracker` は連番の重複・逆行・欠落を管理します。`LegacyIrParser` は旧式6byte IR応答を検査し、`SharedBusIrRequestParser` は共有バス上で1byte IR要求を識別します。末尾の関数は整数値のリトルエンディアン変換です。

### `Rs485.h` — 半二重RS485とバス調停

`Rs485Io` にUART操作をコールバックとして渡し、`Rs485Driver` が受信、DE切替、送信完了待ち、送受信切替待ち、送受信診断をまとめます。`canTransmit` は受信中・送信中や静穏時間不足の送信を避けます。`Rs485MasterArbiter` はMAINが同時に複数のセンサー要求を保持しないようにします。

### `RobotControl.h` — LINE情報・運動学・戦術

- `calculateLine` と `make/decodeLinePacket` は設定済み18センサーだけで検出数/方向を計算し、故障センサーのビットを送信・受信から除外します。角度情報が不明な場合は方向を無効にします。
- `Motion` と `make/decodeMotorPacket` は正規化された前後・左右・旋回指令を扱います。
- `validMotorHardwareConfig` はPWM有効化前にピン重複、車輪値、ドライバー値を検査します。`tb67h450Encode` は4モードをデータシート表へ変換し、`MotorWheelSlew` は反転待ちと加減速制限を行い、`safeMotorUpdate` は無効・期限切れ時に出力を止めます。
- `HeadingController` は方位誤差を最短方向で計算し、大きな一回限りの角度跳躍を保留します。`MainController` は安全条件、FAULTのラッチと明示的復帰、ライン回避、ボール追跡、探索、待機を状態機械として実行します。

### `RobotDevices.h` — センサー監視と補助機器ゲート

`Bno055Monitor` はBNO055の初期化・再試行、読み取り、SYS校正完了に基づく方位有効性を扱います。`KickerController` は有効な指令の立ち上がりで短いキックパルスを出し、連続動作を防ぎます。`DribblerController` は値域とARM・停止・FAULT・ハードウェア設定を確認して出力値を許可します。補助機器ゲートは共通ロジックとして定義されています。

### `BoardConfig.h` — 基板ピンと有効化設定

各基板のRS485ピン、LINEの入力GPIO/故障マスク、MAINのBNO055 I2Cピンと0x28アドレス、方位目標、LINE極性・角度、モーター・キッカー・ドリブラーの設定フラグを管理します。現在、競技ARM、モーターPWM出力、補助機器、LINE極性と実角度は未設定です。

### `common/library.properties` — Arduinoライブラリ情報

共有ヘッダーを `SoccerCommon` ライブラリとしてArduinoビルドから参照するための名前、バージョン、対応アーキテクチャ等を記します。

## 設定

### `config/gpio_profiles.json`

MAIN/IR/LINEの設計候補と標準Pico 2の参考情報をJSONで保持します。MOTORの旧版値は別のLEGACY_REFERENCE欄にのみあり、製造新版の設定表にはありません。実基板の導通は未測定です。

## テスト・検査用コード

### `tests/test_core.cpp`

共通ヘッダーのホスト単体テストです。CRCとフレーム、部分受信・timeout、連番、RS485の送受信順、IR要求識別、LINE判定、4輪変換、方位制御、デバイス監視、FAULT・停止・復帰などをモック入力で確認します。

### `tests/test_integration.cpp`

モック上でMAIN・センサー・MOTOR間のシステム動作をつないで確認します。ボール追跡、ライン優先、センサー通信断、BNO055異常、停止・再ARM、共有バス調停などが対象です。実センサーやRS485配線の電気的動作を試験するものではありません。

### `tests/run_tests.ps1`

`test_core.cpp` と `test_integration.cpp` をC++17でビルド・実行します。g++があれば優先し、なければVisual StudioのC++コンパイラを探します。結果は `tests/results_last_run.txt` に記録します。

### `tests/compile_arduino.ps1`

Arduino CLIを使って4スケッチをRP2350 A/B構成でコンパイルします。コンパイルのみで、基板への書き込みは行いません。結果は `tests/arduino_compile_current.txt` に記録します。

### `tests/check_gpio.py`

GPIOプロファイルの範囲・同一MCU内の重複を検査し、IR/LINEのピン配列とIR追跡部分が元ソースと一致すること、BoardConfigのUART/DE割当、未確定の安全ゲートを確認します。独自の基板配線が導通しているかを測るツールではありません。

## 同一内容のヘッダー

`motor/RobotControl.h` は `common/src/RobotControl.h` と、`motor/Rs485.h` は `common/src/Rs485.h` と、それぞれ現在同一内容です。独立した実装ではなく複製です。変更時は両方を同期してください。
