# MOTORファームウェア引き渡し

## 現在の前提

- 製造されたMOTORは改善後の新版。
- 現存KiCadは改善前の旧版であり、すべてLEGACY_REFERENCE。
- 今回ユーザー報告でTB67H450FNG×4のPWM GPIOは左前J2=13/12、右前J6=11/10、左後J7=9/8、右後J1=7/6。4輪それぞれの回転とMAIN-MOTOR間RS485テストは成功との報告。正転極性、ローラー向き、4輪合成移動、MOTOR側UART/DE、ARM/E-stop、電源定格は未確認。
- 旧版の配線値やDRC結果を現行ボードの設定・不具合判定に使わない。

根拠: [MOTOR_REVISION_DIFF_JA.md](MOTOR_REVISION_DIFF_JA.md)。

## ソフトウェアの状態

motor/motor.inoはパケット形式、CRC/sequence、期限切れ、値域検査、4輪運動学、安全ゲート、TB67H450出力変換を実装する。成功コードのPWM設定を使うが、現行版に対して以下を無効にしている。

- RS485 TX/RX/DE=-1、GPIO数0、検証済みフラグfalse。通信テスト成功は報告されているが、端子設定は不明
- 4ペアのPWM GPIO割当てと許可マスクはユーザー報告値を記録。周波数20kHz、範囲255、最大Duty128
- ドライバー表は設定済み。車輪の位置角・ローラー方向・電気的極性は未設定で、実ハードウェア設定false
- ARM/E-stop/FAULT解除ピン未割当て、入力バイアス未確認
- 競技ARM=false。実PWM出力なし

検証済み通信ピンがなければUARTを初期化しない。起動時のPWM、ARM、E-stop、出力は未設定のまま。CRC/タイムアウトのホストモデル通過は現物の停止動作を保証しない。

## 次の担当者に必要な入力

1. 製造新版の回路図、PCB、BOM、Gerber、ネットリスト、改版識別子。
2. MCU刻印/package、物理信号端子、RS485 TX/RX/DE/A/B、電源レールの導通記録。
3. 実搭載ドライバーの完全な型番、電流検出/VREF回路、電源/保護素子の定格とデータシート。
4. 物理ARM/E-stop/CPU停止時の独立遮断、実装品に一致する真理値表、停止出力の根拠。
5. 4輪のローラー向き、正転極性、実測した4輪合成の前後左右/回転方向と低速挙動。
6. PWM周波数/分解能と通信期限のベンチ測定記録。

設計版と導通測定をレビューするまでBoardConfigを有効化しない。旧版の値から推測して埋めない。接続・駆動・書き込みは行っていない.
