# MAIN → MOTOR 実機確認手順

## 現在の状態

- MAINとMOTORは同じ12 byte形式を使います: `AA 04 [int16 little-endian ×4] XOR 55`。値は -255..255、256=ブレーキです。
- MAIN USBシリアルへ `M 100 100 100 100` の形式で4輪値を送ると、40ms間隔でMOTORへ中継します。`S` は全輪停止です。
- 1コマンドの有効時間は300msです。連続駆動では300ms未満の間隔で指令を送り直してください。送信が止まるとMAINとMOTORの双方がゼロ指令へ戻ります。
- MOTOR制御はユーザー提供の実動作コードに合わせ、PWM200以下即時、200超は±200から10msごとに5ずつ加速、逆転前200ms停止、0=停止、256=ブレーキです。起動時は停止値です。
- この作業ではアップロード、RS485実機通信、PWM、実モーターを試していません。ユーザーが実機確認したのは正転・逆転・停止・ブレーキです。

## 1. 電源を入れる前に

1. MAIN/MOTOR基板の型番、改版、MCU刻印を記録します。MOTOR親基板はZIPのBOMでRP2354Aですが、実機刻印を照合してください。ZIP子基板のIR4427系回路はユーザー報告のTB67H450×4実機とは異なります。
2. 電源を切った状態で、MOTOR配列順のIN1={GP6,12,11,8}、IN2={GP7,13,10,9}を現物のドライバー入力まで導通確認します。表は順にJ1右後、J2左前、J6右前、J7左後です。
3. TX=GP0、RX=GP1、DE=GP2候補をMAX3485のDI/RO/DEへ照合します。`/RE`の接続、DEの極性、A/B、GND、終端、バイアスも回路図と測定で確認します。ファームウェアはDE=LOWで受信、HIGHで送信する前提です。
4. TB67H450の実装型番、モーター電源、過電流保護、電流制限、独立した電源遮断/E-stopを確認します。安全遮断が未確認ならモーター電源を接続しません。

## 2. モーター電源なしでRS485を確認

MAIN/MOTORを書き込んでUSBシリアルを開きます。MAINは起動時に`AUTO IR`で待ち、最初の新鮮なIRボール検出で一度だけ自動ARMします。モーター電源なしでリンクを確認し、起動自動ARM待ちを解除する場合はUSBから`S`を送ります。期待する停止時の12 byteは次のとおりです。

```text
AA 04 00 00 00 00 00 00 00 00 AE 55
```

オシロスコープまたはRS485アナライザーでMAINの送信、DE切替、A/B波形、MOTORの受信を観測します。MOTORのUSBログで `RS485_rx` が増え、checksum/format/range/frame timeoutが増えないことを見ます。MOTORはACKを返しません。これで確認できるのはその時点のリンク動作で、車輪方向や通信断時の実停止までは確認できません。

## 3. MAINからの直接指令

USBシリアルを115200bpsで開き、改行付きで次のように入力します。

```text
M 100 100 100 100
```

各値はフレーム順の4モーターへ対応します。`-255..255`が正逆PWM、`256`がブレーキです。直接指令の前に`S`を送って起動時の自動ARM待ちを解除してください。停止するには `S` を送るか、300ms以内に次の指令を送らないでください。起動時にIRでボールを検出すると最大5秒の試験走行を一度だけ行います。

## 4. 競技制御

`M`指令はフレームの4値を直接送ります。通常AUTOは安全・車輪設定ゲートが閉じているため停止します。起動時は`AUTO IR`で待機し、新鮮なIR応答でボールを検出すると一度だけ自動ARMします。5秒で解除され、各輪PWMは16/255までです。IR方向は0°前方・30°刻みで区分し、正面だけ前進、それ以外は旋回します。ボール消失、IR不正値、IR通信期限切れ、`S`は停止します。LINE照会は停止するため境界検出はありません。床上での使用はせず、車輪を浮かせて確認してください。

このテストモードはIR検出によるソフトウェア自動ARMと仮の車輪合成方向を使い、物理ARM/E-stopの代わりにはなりません。まず車輪を浮かせ、独立した電源遮断と電流制限つき電源を用いて動作の向きと停止を短く確認します。車輪の方向、実MAIN↔IR/MOTORのRS485、通信断停止を実機確認するまで床上では走らせません。Sのゼロ指令はRS485の現在の受信/送信区間後に優先送信され、MOTOR側も指令が300ms途絶えると停止します。

まず車輪を浮かせ、独立した電源遮断が手元で動くことを確認し、電流制限つき電源で実施します。MAINのセンサー状態を一つずつ作り、USBログとRS485フレームを見ながら短く動かします。MAINからの正転・逆転・通常停止、4輪の合成方向、異常フレーム後の停止、通信を切った後300ms以内の停止を確認します。受信側は256=ブレーキを処理しますが、現在のMAINのMotion変換は停止に0を送り、256を生成しません。MAINからの明示的なブレーキ要求を追加するまでは、ブレーキをMAIN連携試験の合格項目にしません。反転を試す前に停止とE-stopを確認します。

車輪の向きが予測と違う、停止しない、電流が急増する、A/B送信が重なる、E-stopが機能しない場合は直ちに独立遮断し、駆動を続けません。試験値、基板改版、配線、ログ、停止時間を記録します。

**MAIN/MOTORの実機RS485通信は未試験です。Arduinoコンパイルとホストテストは実機で動く証明ではありません。**
