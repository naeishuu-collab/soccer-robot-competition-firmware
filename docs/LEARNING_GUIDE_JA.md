# 4基板コードを説明する学習ガイド

この教材はcompetitionのソフトウェアモデルに合わせています。製造されたMOTOR新版のKiCadはなく、旧版ピン値を実機設定へ移さないでください。例は実機動作の確認ではありません。各練習の答えはその章の直後にあります。

## 1. Arduinoのsetupとloop

- 説明: setupは電源投入後に一度、loopは繰り返し実行します。
- コード: 各INOにsetupとloopが一つずつあります。
- 例: setupでUART開始、loopで受信を処理します。
- 練習: MAINがsetupで設定する通信機能は何ですか。
- 解答: MAIN/IR/LINEはSerial1（ハードウェアUART0）を通信候補として設定し、MOTOR新版のUARTは未設定です。MAINはWireでBNO055候補を初期化します。Serial2とSerialPIOは使いません。
- 発表例: 「最初に通信を準備し、その後はloopでセンサー情報を更新します。」

## 2. GPIO

- 説明: GPIOは入力や出力に設定できるチップ端子です。基板上の配線有無は別確認です。
- コード: BoardConfig.hに通信とI2CのGPIO、LINE INOに24ピン配列があります。
- 例: pinMode(pin, INPUT)で読み取りを準備します。
- 練習: RP2354AのGPIO数と基板配線は同じ意味ですか。
- 解答: 違います。チップでは30本ですが、キャリア上で接続されたかは回路図確認が必要です。
- 発表例: 「ピン番号がチップで使えても、基板のコネクターまで配線されたか確認します。」

## 3. digitalReadとdigitalWrite

- 説明: digitalReadはHIGH/LOW入力を読み、digitalWriteはデジタル出力を設定します。
- コード: LINEは24個をdigitalRead、RS485 DEはdigitalWriteで切替えます。
- 例: raw bit i = HIGHなら1、LOWなら0です。
- 練習: 生レベルHIGHは白線検出を意味しますか。
- 解答: 極性が未確定なので意味は決められません。
- 発表例: 「まず読み取った電圧論理を保存し、白線の意味は測定してから決めます。」

## 4. UARTとI2C

- 説明: UARTはTX/RXでバイトを送受信し、I2CはSDA/SCLの2線でアドレス付き通信をします。
- コード: MAINはIR用UARTとWireでBNO055を扱います。
- 例: Wire.setSDA(4)、Wire.setSCL(5)、Wire.begin()です。
- 練習: BNO055にGPIO4/5を使う場合に確認することは。
- 解答: 基板導通、プルアップ、電圧、アドレス、クロックです。
- 発表例: 「I2Cではアドレス確認と配線のプルアップも必要です。」

## 5. RS485

- 説明: RS485は差動信号の通信方式です。MAX3485は半二重なので送受信の向きを切替えます。
- コード: Rs485.hのsendRs485はDE、UART送信、flush後に受信へ戻します。
- 例: DE HIGH→write→flush→DE LOW。
- 練習: 共有バスで同時に送信すると何が起こりますか。
- 解答: ドライバー同士が衝突するので、送信権管理が必要です。
- 発表例: 「配線が共有か独立かを回路図で確認してから通信順を決めます。」

## 6. センサーデータ

- 説明: センサー値は物理量そのものとは限らず、校正と単位確認が必要です。
- コード: IR strengthは相対信号、LINEはraw 24bitです。
- 例: 24bitのbit 3が1ならLINEセンサー配列の3番目がHIGH。
- 練習: IRのrelativeSignalをcmと呼べますか。
- 解答: いいえ。cm変換の校正がありません。
- 発表例: 「信号強度の相対値であり、距離とは区別します。」

## 7. 配列と構造体

- 説明: 配列は同じ種類を並べ、構造体は関連データをまとめます。
- コード: kSensorPinsは24要素、Motionはx/y/turnをまとめます。
- 例: Motion m{0,1,0}は前方向の正規化指令です。
- 練習: LINEの24bitの1bitは何に対応しますか。
- 解答: センサー番号とその生レベルに対応します。
- 発表例: 「配列番号とビット位置を対応させて、入力をまとめて扱います。」

## 8. クラスと関数

- 説明: 関数は処理のまとまり、クラスは処理と内部状態を一緒に管理します。
- コード: PacketParserは受信途中状態、MainControllerはFAULT保持状態を持ちます。
- 例: parser.feed(byte, time, packet)に1byte渡します。
- 練習: MainControllerを関数だけでなくクラスにする理由は。
- 解答: avoidingやfaultLatchedなど複数回の呼び出しを越える状態を保持するためです。
- 発表例: 「制御の途中状態をコントローラー内部へまとめています。」

## 9. 三角関数

- 説明: sinとcosは角度を直交する成分へ分ける計算です。
- コード: IRのcosTable/sinTable、MAINの移動ベクトル、LINE角度計算で使います。
- 例: 角度0の前進指令ではx=sin0=0、y=cos0=1。
- 練習: 角度90度の移動は右方向成分がどうなりますか。
- 解答: x=sin90=1、y=cos90=0です。
- 発表例: 「角度をx方向とy方向へ分解して車体の動きに変換します。」

## 10. ベクトル

- 説明: 大きさと向きを持つ矢印です。複数センサーの向きを足し合わせられます。
- コード: IRでは検出回数をベクトルの重みにします。
- 例: 右と左が同じ強さなら横成分が打ち消し合います。
- 練習: 12個のIR出力を足すと何が分かりますか。
- 解答: 合成ベクトルの方向からボール方向を推定します。
- 発表例: 「強く反応したセンサーを重くして、方向の矢印を合成します。」

## 11. atan2

- 説明: atan2はX/Yの符号も見て角度を返す関数です。
- コード: IRはatan2(vectorY, vectorX)です。
- 例: vectorX=1、vectorY=0なら0度です。
- 練習: atan2だけで距離も分かりますか。
- 解答: いいえ。向きだけです。
- 発表例: 「合成したXとYから角度を求めます。」

## 12. 角度の正規化

- 説明: 円周上の角度を決まった範囲に収めます。
- コード: normalizeDegreesは0〜360、IR normalizeAngleも同様です。
- 例: -10度は350度、370度は10度です。
- 練習: target=1,current=359の最短誤差を求めます。
- 解答: +2度です。
- 発表例: 「角度は一周すると元に戻るので、最短側の差を使います。」

## 13. PID制御

- 説明: Pは現在の誤差、Iは誤差の蓄積、Dは誤差変化の速さを使います。
- コード: HeadingControllerはPのみで、turn=0.012×errorを±0.35へ制限します。
- 例: 誤差10度なら未制限出力0.12です。
- 練習: この実装をPIDと呼べますか。
- 解答: いいえ。積分Iと微分DがないP制御です。
- 発表例: 「まず比例制御から始め、実機試験後に必要な調整を検討します。」

## 14. 4輪オムニの運動学

- 説明: 前後・左右・旋回を4輪の方向速度へ合成します。
- コード: omniKinematicsは位置、駆動角、極性からwheel_iを計算します。
- 例: wheel_i=polarity×(並進投影+旋回投影)。
- 練習: 車輪の極性を間違えると何が起きますか。
- 解答: 指令方向と回転方向が逆になり、車体の動きが意図と違います。
- 発表例: 「理論式の後、車輪ごとの実測で番号と符号を合わせます。」

## 15. CRC16

- 説明: CRCは通信データの誤りを見つけるチェック値です。
- コード: crc16は初期FFFF、多項式1021でビット演算します。
- 例: 受信CRCと計算CRCが違えばフレームを捨てます。
- 練習: CRCが一致したら送信者が安全だと証明できますか。
- 解答: いいえ。破損検出であり認証ではありません。
- 発表例: 「データの偶発的な破損を検出しますが、内容の安全検査も別に行います。」

## 16. 状態機械

- 説明: 状態と条件から次の行動を選ぶ方法です。
- コード: MainControllerはSEARCH、APPROACH、AVOID、FAULTなどを選択します。
- 例: LINE検出ならボールより先にAVOID。
- 練習: FAULT後に自動で走行再開しますか。
- 解答: しません。復帰条件とARMし直しが必要です。
- 発表例: 「優先順位と遷移条件を状態機械に集めて説明しやすくしています。」

## 17. タイムアウト

- 説明: 決めた時間に返答やデータが来なければ異常とする方法です。
- コード: IR返答15ms、LINE鮮度100ms、MOTOR指令100msなど。
- 例: MOTOR指令が100ms来なければ停止値へ戻ります。
- 練習: 途中フレームのtimeoutは何msですか。
- 解答: PacketParserはbyte間8msです。IR途中パケットは10msです。
- 発表例: 「古いセンサーデータを使わないよう期限を設けています。」

## 18. 安全停止

- 説明: 不確かな状態では出力を止め、復帰を明示操作にします。
- コード: 起動無効、MOTORローカル期限、FAULTラッチ、アクセサリーゲート。
- 例: LINE極性不明の状態でARMされたらFAULT。
- 練習: ソフトの停止がモーター電源を物理的に切れる証拠ですか。
- 解答: いいえ。電源遮断回路と実機試験が必要です。
- 発表例: 「ソフトと独立した物理E-stopの確認を今後行います。」

## 19. テスト

- 説明: 単体試験は個々の計算、統合試験はデータ経路全体を模擬します。
- コード: test_core.cpp、test_integration.cpp、check_gpio.py。
- 例: CRC破損、角度境界、通信断→停止を試します。
- 練習: 今回の統合テストは実機E2Eですか。
- 解答: いいえ。ホスト上の模擬テストです。
- 発表例: 「論理は模擬確認しましたが、電気的な信号は未検証です。」

## 20. ロボット全体のデータフロー

- 説明: センサーを読み、通信し、状態を決め、運動を計算し、出力します。
- コード: IR/LINE→MAINのMainController→MOTORのPacketParser/運動学。
- 例: IR角度→接近ベクトル、BNO角度→旋回指令。
- 練習: MAINから指令が止まったとき最後に停止するのはどこですか。
- 解答: MOTOR側の100msローカル通信期限です。
- 発表例: 「MAINの判断だけでなく、MOTORにも独立した通信期限を置いています。」

# 理解度チェック 総合30問

各問に答えた後で答え欄を見てください。

1. setupとloopの役割は何ですか。  
答え: setupは一度の初期化、loopは繰り返し処理です。

2. RP2354AのGPIO数はいくつですか。  
答え: 30本です。自作基板上の配線本数とは別です。

3. RP2354BのGPIO数はいくつですか。  
答え: 48本です。実コネクター配線は図面で確認します。

4. UARTは主にどの信号を使いますか。  
答え: TXとRXです。GNDと電圧レベルも必要です。

5. I2Cで使う2信号は何ですか。  
答え: SDAとSCLです。

6. RS485のMAX3485は全二重ですか。  
答え: 半二重です。

7. IRは何個のセンサーを使いますか。  
答え: 12個です。

8. IRのセンサー0の方向は何度ですか。  
答え: 正面を0度とする既存設定です。

9. IR方向計算でベクトルを作る重みは何ですか。  
答え: 5msサンプル内の検出回数です。

10. atan2の出力は方向ですか、距離ですか。  
答え: 方向です。

11. IR相対強度は何cmですか。  
答え: 物理距離ではなく相対指標です。

12. IR予測時間は何msですか。  
答え: 30ms先です。

13. LINEの何を保持しますか。  
答え: GPIO2〜25の24個の生レベルを24bitで保持します。

14. LINE極性は確定済みですか。  
答え: いいえ。設定を無効にしています。

15. LINE角度表をなぜ均等にしてはいけませんか。  
答え: 実配置が不均等で測定値が未確認だからです。

16. BNO055はMAINの何に接続する予定ですか。  
答え: I2C、SDA=GPIO4、SCL=GPIO5です。

17. BNO方位を有効にする校正条件は何ですか。  
答え: 現在のモニターではSYS calibrationが3です。

18. 359度と1度の差はいくつですか。  
答え: 最短側で2度です。

19. HeadingControllerはPIDですか。  
答え: P制御です。

20. CRC16が一致する意味は何ですか。  
答え: 対象データの破損が検出されなかったことです。安全や真正性の保証ではありません。

21. 共通フレームの開始バイトは何ですか。  
答え: A5 5Aです。

22. 途中フレームの共通パーサーtimeoutは何msですか。  
答え: 8msです。

23. 8bit sequenceは255の次に何になりますか。  
答え: 0です。差分1なので周回として正常です。

24. LINEとボールが同時に検出されたら何を優先しますか。  
答え: LINE回避です。

25. LINE方向が曖昧ならどうしますか。  
答え: 逃げる方向を推測せず停止します。

26. MainControllerのFAULTは異常消失だけで解除されますか。  
答え: いいえ。明示クリア、500ms正常、ARM解除と再ARMが必要です。

27. MOTOR通信timeoutは何msですか。  
答え: 100msです。

28. 4輪の最大出力が1を超えた場合何をしますか。  
答え: 4輪値を最大絶対値で割り、比率を保って正規化します。

29. 今回4スケッチをコンパイルしたコア版は何ですか。  
答え: Arduino-Pico 6.3.2です。

30. 実機でまだ確認していない代表例を3つ挙げてください。  
答え: 回路図とGPIO導通、BNO/RS485の実通信、モータードライバー停止と走行です。

## 自分で説明するときの確認

コードの行を暗記するより、「入力は何か」「計算は何か」「異常時はどう止まるか」「実機で何が未確認か」の順で話してください。分からない実機値を推測して答えず、測定が必要だと説明するのが正確です。
