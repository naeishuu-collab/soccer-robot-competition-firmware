# 2026-11-28 白線停止ログの調査

対象ログは `READY=1`、`ESCAPE`、`LINE_HAZARD=1`、`SAFE=0000`、`ESCAPE_MASK=0000`、白線方位・距離不明。MAINはカメラが示す退避候補が前後ともないため `NO_SAFE_ESCAPE` にして全輪0とする。`WHITE_LINE=1` は現在の白線方位が有効という意味ではなく、現在方位あり **または** 退避要求あり。IR応答と計算上のPWMは正常で、MOTORに送られるのは停止指令。

OpenMVの危険は現在の確定候補・未確定候補・保持履歴の和。近接の確定候補が消えても200ms未満は退避要求を保持し、再観測で2フレーム以上、かつ最後の危険観測から100ms以上経過しない履歴は、遮蔽が続く限り時間だけで消えない。SAFEは観測範囲から危険を除いたもの、ESCAPEはさらに安全な前後候補に限る。従って白線が現在見えない、視野端で距離が測れない、観測欠落、複数の危険、自己像や反射など複数の場面で同じログになり得る。提示されたMAINログだけではどれかは確定できない。

版2は、現在の白線の方位が分かっていても距離が視野端で不明なら、UARTの方位まで不明にしていた。版3は方位と距離の有効性を独立して送る。距離は推測しない。カメラの `i` の `HELD_AGE_MS_AND_CLEAR_FRAMES`、観測・未知・現在／履歴ブロック、拒否方向と `RAYS` を同時刻の画像と照合する。異なる危険履歴が合成された場合には最寄りの線だけで退避先を決めない。

ユーザー提示相当の `READY|ESCAPE|LINE_HAZARD`、方位不明、SAFE・ESCAPEとも0の入力では、修正後も `NO_SAFE_ESCAPE` とPWM全輪0を維持する。実際に安全な退避先や誤検知を証明する情報がないため、このログだけを根拠に停止を解除しない。候補が再観測された安全方向なら退避し、危険履歴が必要な観測条件で解除された後は追尾へ復帰する。誤検知の実原因、実画像による検出率、実機での停止改善は未確認。
