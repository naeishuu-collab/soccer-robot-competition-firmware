# 千葉ノード向けフィールドと未校正走行

## 適用ルールと現状

[2027千葉ノードの2026年11月11日告知](https://rcjj-kanto.org/chiba/archives/2621)は2026年日本語版第1版の適用と、World Class InfraredのIRゴルフボール・ボール捕獲ゾーン1.5cmを指定する。対応する[2026年1月21日ルール2.6、2.8](https://robocup-junior.github.io/soccer-rules/2026-soccer-draft-rules/rules.html)はロボットのペナルティエリアへの完全進入を禁止する。部分進入中の接触・プッシングや同一チーム2台の部分進入にも制限がある。白線を見ただけで無条件に通過できる規則ではない。告知の日本語PDFの本文をこの環境では直接抽出できなかったため、当日ローカルルールや疑問点は主催者に確認する。

[公式フィールド仕様](https://robocup-junior.github.io/soccer-rules/master/field_specification.html)の国際基準はプレー面158×219cm、ペナルティエリア25×80cm、前方の角半径15cm、白線幅20mm±10%。会場が同じ寸法かは未確認で、実測した値を優先する。

現行カメラは距離推定と24方向走査、黄青ゴール方位を出すが、白線とゴールの対応、複数線の形状、自己位置、カメラ死角、機体輪郭の誤差が未校正。実画像の正解データもない。境界線とペナルティ線を区別する精度や競技規則上の部分進入余裕を証明できないため、全て `UNKNOWN_LINE`（信頼度未評価）と表示し従来の接近制限を維持する。ゴールが見えるだけで分類・解除はしない。識別、部分進入と完全進入の判定、識別別の履歴、不要停止解消は未実装。UART版1を変更しない。

将来は、各線成分の複数方向の点と連続性・曲率・端点、ゴールの両端と方向、フレーム間対応、実フィールド寸法および距離・方位の誤差を用いて複数の位置仮説を作る。異なる線種が整合する、ゴールが不明、死角が含まれる、姿勢が未確定のときはUNKNOWNとし閉鎖する。高信頼のペナルティ線でも、機体輪郭と制動後の最悪軌跡が完全進入を防ぐことを別途確認するまで通過を許可しない。外周線が同時に存在する場合は別成分として保持し、外周とUNKNOWNの危険を優先する。この設計は未実装で、分類の信頼度は未評価。

## 車輪を浮かせた診断

実機操作は別途行う。作業者と電源遮断担当を決め、機体を固定し全車輪を床から離す。障害物や指を車輪から離し、いつでも電源を切れる状態にする。競技では診断ビルドを使用しない。MAIN・IR・カメラの通信が正常でなければ診断は動かない。

診断用MAINのUSBシリアルで `s` を送って停止、`M` でモーター試験、`1`〜`4` で各輪を選ぶ。`g` の後に `R` を一度送ると最大200msだけPWM 160で動き、更新がなければ停止する。各輪の動きを記録し、毎回 `s` で停止する。`5` と `6` は推定横移動パターンA `-160,160,-160,160` とB `160,-160,160,-160` の**未確認候補**。機体の左右方向を示すものではなく競技モードでは使われない。同じ手順で各車輪の正逆のみを確認し、停止と反転待機も確認する。通信断、USB切断、手動停止、200msのデッドマンを確認してから次へ進む。

## 実測記録と進め方

1. 機体前方と車輪番号をテープで印し、機体外形の半幅・半長、車輪の正逆を記録する。基板番号とファームウェアの版も控える。
2. 開放空間で遮断担当を配置し、公式ルールを守れる試験フィールドで前進・後退・A/B候補・左右旋回の向きを一つずつ短く測る。車輪を浮かせた結果だけから床上軌跡を決めない。現時点の診断は床上試験用ではなく、床上の横移動候補を自動で有効化しない。
3. PWM、電池電圧、床材、方向別に距離と時間を複数回測り、最大速度、最悪の停止距離、旋回中に機体外周が通った範囲、反転保護の影響を動画・目盛り・時刻で記録する。連続通信遅延も含めた最大停止までの移動を測り、誤差と余裕を加える。
4. OpenMVの画像と `i` ログを保存し、前後左右・角・ゴール前の外周とペナルティ線、両方同時、ゴールなし、逆光、死角を正解ラベル付きで取得する。実寸と推定距離、角度、死角に入る位置を同時に記録する。
5. 分類器を実装した後は、撮影条件ごとに外周→ペナルティの危険な誤分類、UNKNOWN率、ペナルティ→外周の不要停止を別々に数える。訓練と評価に異なる撮影を使い、実画像評価なしに通過許可しない。
6. 経路候補の設定は `competition/main/line_safety.h` の `CompetitionSweep`。既定は全値ゼロで未校正。`halfWidthCm, halfLengthCm, fullTravelCm, fullYawDeg, marginCm, observedCm` の順だが、値を埋めるだけで運動モデルや安全性が証明されるわけではない。候補式の車輪座標・旋回符号・停止範囲・視野を実測と突き合わせてから別途検証し、架空値や合成テスト値を本番に入れない。
