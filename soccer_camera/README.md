# サッカーロボット：カメラあり版

> 現行の動作・書き込み方法は [最終版のやさしい説明](docs/FINAL_GUIDE_JA.md) を参照してください。以下は旧版の説明で、停止条件やBNO055については最終版と異なります。

## 現行版コード

書き込みに使う現行版は `main/`・`ir/`・`motor/` の3基板と `openmv/goal_wall_navigation.py` です。OpenMVには `openmv/camera_calibration.py` も設定して保存します。`line/` は今回の chase 構成では未使用です。

`chase_verified/` と `legacy_before_chase/` は比較・検査用の保存版で、書き込みには使いません。`common/`・`tests/` はホスト検査用、`docs/` は手順と記録、`config/` は検査設定です。

## VS Codeで開く

VS Codeの「フォルダーを開く」で `soccer_camera` を選びます。

## 書き込みと運転

- MAINは `main/main.ino`、MOTORは `motor/motor.ino` を組で書き込みます。OpenMVは `openmv/goal_wall_navigation.py` を `main.py` として保存し、実機の `camera_calibration.py` を同じ場所に置きます。今回のカメラとMAINは8方向の床情報を含む新しいUART形式で通信します。
- IRは `ir/ir.ino` または実機確認済み `chase (3).zip` のIRスケッチを使えます。MAINは30 ms間隔でIRに問い合わせ、IRは要求ごとに5 ms測定します。
- 電源投入後、カメラとIRの通信が有効になり、ボールと進行可能な床を確認すると自動で追跡します。IRが応答している間は、最後に採用した球の方位を最大90 ms保持します。45°を超える変化は、25°以内で一致する連続2回の検出で採用します。ロック期限切れ、進行先の床が確認できないとき、通信が途絶したときは停止します。条件が戻ると自動で再開します。起動・復帰の動作確認は車輪を浮かせて行います。

## 役割分担

- IRがボールの有無と方位を測ります。カメラが緑床と白線を確認し、走行可能な方向と白線から離れる方向をMAINに送ります。OpenMV IDEには白線の方向数・最短距離・回避モードと、青・黄それぞれのゴール枠が表示されます。
- MAINはカメラが許可した8方向の中央角を使って、ボールへ向かう走行、境界回避、停止を選びます。カメラは近い境界に近づく方向を退避候補から除き、走行判定が変わるとすぐに送信します。球は機体で押す・弾く運用です。キッカー出力GPIO11は起動時にLOWにします。ゴール枠はプレビュー用です。
- MOTORは4輪出力を生成します。同じ極性での再開はPWM更新周期で行い、逆極性への切り替えには200 msの待ちを適用します。回避で逆転する場合は4輪をそろえて停止し、有効な指令が100 ms途絶えると出力を止め、次の有効な指令で復帰します。

白線の回避距離25 cmは暫定値です。白線距離はミラー軸からの距離です。実機で前後左右の検出と停止距離、車輪極性、IR・カメラ・MOTORの通信断、復帰時の自動再開を確認してから、出力と距離を調整してください。 [OpenMV校正手順](docs/OPENMV_CALIBRATION_JA.md)
