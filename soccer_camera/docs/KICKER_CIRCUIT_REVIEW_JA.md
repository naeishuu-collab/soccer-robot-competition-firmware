# キッカー回路レビュー

## 判定

ZIP内キッカー設計資料を確認した。蓄電式の高電圧回路として扱う必要があるが、実装基板との一致、部品定格、充電禁止、残留放電が確定しない。**電源接続・充電・負荷接続・発射はNO-GO**。実機操作は行っていない。

## VERIFIED_DESIGN（ZIP内 kick/kika）

| 項目 | 設計資料の表記 |
|---|---|
| 電源/電圧系 | J3に+BATT入力、回路上に+40Vレール |
| 蓄電部 | C5=1000uF、C3=220uF |
| スイッチ | Q2がJ1負荷をスイッチ |
| 制御端子 | J2にIO/GND |
| 設計上の欠落 | U1/U2のValue空欄、C3/C5耐圧不明、BOM LCSC欄空、MAINへのGPIO/通信IF不明 |

DRC未接続0件は実装後の動作や安全を示さない。KiCad記号だけで部品型番を推定しない。

## 実装したソフトウェア境界

- KickerController: DISARMED/READY/FIRING/COOLDOWN/FAULT、要求立ち上がり、鮮度・ARM・E-stop・FAULT・ボール・姿勢・ラインのゲート、イベント履歴。
- MAINからkickerRequestAllowedを呼び、要求を状態機械に渡す。要求ポリシーとハードウェアゲートは、利用者申告のMAIN GPIO11配線に対して有効化した（2026-11-18）。姿勢窓（BNO055）は未較正のためfalseのまま。
- mockPulseActiveはホストモデル用。MAINに物理出力アダプター/GPIOはない。60ms pulse/1000ms cooldownはテスト専用で、実機値ではない。
- 実回路の充電・発射を制御するコードや許可設定はない。

## ファームウェア側の有効化（2026-11-18）

利用者からMAIN GPIO11へのキッカー接続の申告があったため、ソフトウェア側のゲートのみ有効化した。

- `kKickerPin = 11`。起動時にLOWへ設定し、状態機械のパルス出力中だけHIGHにする。
- `kKickerHardwareConfigured` と `kKickerRequestPolicyConfigured` をtrueに変更。
- キック判定は未較正のBNO055ではなく、**IRボール方位**を使用する。ボールが正面 ±30° のときだけ要求する。
- 発射条件：接近中（kApproachBall）＋ARM＋E-stopなし＋FAULTなし＋ボール鮮度＋ラインクリア＋正面方位。要求の立ち上がりのみで1回発射し、保持しても再発射しない。
- パルス30ms／クールダウン2000msは**未測定の暫定値**。実機の充電・放電特性を測るまで競技では使用しない。
- LINE故障中はAUTO IR（LINE不使用）でも発射可能とした。IRボール方位が正面±30°、またはOpenMVの0x20キック要求で発射する。AUTO IRではLINE鮮度・ラインクリア・MAIN E-stopのソフトゲートを外しているため、物理電源遮断が唯一の停止手段이다。

**注意：これは回路の安全性を確認したものではない。** 上記「判定」のNO-GO（蓄電コンデンサの耐圧、充電禁止、残留放電、J2信号の極性・絶縁、独立非常停止）は引き続き有効。ファームウェアを書き込んで通電・充電・発射試験を行う前に、回路側の証拠をそろえること。

## 実機再開に必要な証拠

1. 製造版回路図/BOMと実部品刻印/型番を照合する。
2. コンデンサー、半導体、配線、負荷、コネクターの最大電圧/電流/温度定格を確認する。
3. 独立充電禁止とE-stopがMAIN/CPU停止時にも働く根拠を示す。
4. 電源OFFで放電経路と安全な残留電圧確認点を確定し、計測手順をレビューする。
5. 実負荷なしの計測計画を専門家レビュー後に作る。

確認までキッカーをロボットへ接続しない。設計表記だけで安全を保証しない.
