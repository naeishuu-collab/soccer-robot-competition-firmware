# OpenMV H7 Plus 全方位カメラの校正

メーカーの標準レンズを通してミラーを撮影する構成を想定します。ミラーと機体を固定した状態で校正し、取付位置や解像度を変えたときは測り直します。

| スクリプト | 用途 |
|---|---|
| `goal_wall_navigation.py` | 競技用。カメラの `main.py` として保存し、同じ場所に `camera_calibration.py` を置く。 |
| `camera_only_display.py` | ゴールの輪郭、ミラー中心・リング・正面、壁／白線の検出点と現在のモードを表示する。UARTは初期設定で無効。 |
| `debug_thresholds.py` | ゴール候補数、面積とミラー領域での除外数、撮像設定、FPS、任意の位置のLAB分布を記録する。 |
| `wall_only.py` | 黒壁の候補と床を走査した境界点を比較する。診断用の旧形式 `0x02` と `0x14` を送信する。 |

診断用スクリプトを実行する場合は、`goal_wall_navigation.py` を元のファイル名で置き、`camera_calibration.py` も同じ場所に置きます。MAINと本番カメラのファームウェアは組で更新します。配線は OpenMV UART3 TX → MAIN GP3 (Serial2 RX) と GND共通、9600 bpsです。MAIN GP2はTXです。

## カメラの設定

1. `debug_thresholds.py` で画像寸法を確認し、`FRAME_SIZE` と `IMAGE_SIZE` を設定します。初期値はQVGAです。円が欠ける場合は、H7 Plusで使える解像度を選び直して測定します。
2. ピクセル座標で `MIRROR_CENTER` と `MIRROR_RING` を測ります。内半径の内側には機体の映り込み、外半径の外側には競技面より高い背景が主に入るよう、画像で確認します。次に前・右・後・左の目印を使って `FRONT_DEG` と `CLOCKWISE` を設定し、正面から時計回りに0°・90°・180°・270°となることを確認します。
3. 床上の目印をミラー軸から10、15、20、30、40、50、60 cmなどの既知距離に置き、写った半径を測ります。`GROUND_POINTS` に `(半径px, 距離cm)` の組を距離順に入力します。半径は増加、減少どちらでも使えますが途中で反転する設定は無効です。最初の点は白線回避距離以内、最後は50 cm以上が必要です。白線回避距離以内に緑2点と白線の先頭点を取れるよう、近距離を実測します。同じ距離を四方向で確認し、方位による差が大きい場合はミラーの中心と傾きを調整します。
4. `SAMPLE_ROIS` に映像上の黄・青・黒壁・緑床・白線の小矩形を設定し、LAB分布を計測します。静止時と旋回時、通常照明と陰で露出・ゲインを比べ、必要なら `EXPOSURE_US`、`GAIN_DB`、`RGB_GAIN_DB` を固定してから色しきい値を調整します。ゴール最小画素数はコート中央約110 cmと反対側約219 cmで確認します。機体の赤外照明は消灯した状態でテストします。
5. 試合の各ハーフ前に `TARGET_GOAL` を攻撃先の `"YELLOW"` または `"BLUE"` に設定して再起動します。攻撃色はプレビューのゴール枠に使います。ミラーや床面の設定が不十分なときは `WAIT` になります。

## WAIT が続くとき

OpenMV IDEで映像を表示し、`MODE: WAIT` の下に出る項目から順に確認します。設定はOpenMVドライブ上の `camera_calibration.py` に保存し、スクリプトを停止して起動し直します。

| 画面表示 | 確認する項目 |
|---|---|
| `SET IMAGE_SIZE 320x240` など | 表示された実際の幅と高さを `IMAGE_SIZE` に入力します。例は `(320, 240)` です。 |
| `CHECK MIRROR_CENTER/RING` | IDEの映像で中心と内外半径を測ります。外円全体が画像に収まると、白い円と機体正面の線が表示されます。 |
| `CHECK GROUND_POINTS` | 機体を緑の床に置き、上記手順3の距離と半径を測ります。半径は内円と外円の間に収めます。 |
| `FLOOR 8/24 CHECK PATH` など | 追跡には緑床が12方向以上見え、進行方向の中央と左右15°・30°が空いている必要があります。回避も退避先の床が見える方向に限ります。 |
| `SLOW FRAME 120ms > 100ms` など | 撮像から走行判定までが100 msを超えています。MAINのUSBログでも `CAM` で状態を確認できます。 |
| `WHITE LINE: DETECTED (3, 24 cm)` | 3方向で白線を検出し、最も近い検出点がミラー軸から約24 cmです。白い十字が検出点です。 |
| `WHITE LINE: NOT DETECTED` / `WHITE LINE: CHECK CALIBRATION` | 白線の検出がない場合、または床面の走査に必要なミラー・距離設定を確認する場合に表示されます。 |

コート中央では床の条件を満たすと `TRACK IR` になります。IRがボールを検出するとMAINが進行方向を選び、カメラの床情報でその方向を確認します。ゴール色検出は画面表示に使います。

## MAINの設定と確認

- 車輪を浮かせ、ボールを前後左右に置いて、MAINの `DIR` とMOTORの回転方向を確認します。続いて白線・黒壁の回避と、カメラまたはIR信号を切ったときの停止と、復帰後に `A` を送るまで駆動しないことを試します。
- 競技用UARTの送信目標は50 ms間隔です。撮像から判定までに100 msを超えた場合は `WAIT` を送ります。MAINは最後の有効なカメラパケットから約200 msで失効させます。プレビュー用の色検出と描画は判定・送信処理の後に行います。表示が不要な場合は `main_loop(send_uart=True, display=False)` で起動できます。MAINのUSBログでは `CAM` が0でWAIT、1で回避、2でIR追跡を表します。

公式コートは白線内158×219 cm、外周182×243 cm、外エリア片側12 cm、ゴール幅60 cmです。近接回避は白線を直接走査し、黒壁を補助に使います。ペナルティエリアの白線にも同じ近接回避を適用します。白線の種類や機体の絶対位置の分類、見えない線を越えたあとの復帰は実機確認が必要です。25 cmの白線回避距離と30 cmの黒壁回避距離は暫定です。機体寸法、見え方、実測した停止距離に合わせて調整します。 [公式フィールド仕様](https://robocup-junior.github.io/soccer-rules/master/field_specification.html)

## 壁診断の見方

`wall_only.py` は黒い領域の診断用です。新規検出は150画素以上、近くに継続する候補は100画素以上とし、中心位置を平滑化します。候補が消えたら保持を解除し、次の送信周期で未検出を送ります。赤枠は現在の候補、黄色い十字は平滑化した中心です。黒い家具・影も検出し得るため、赤枠だけでは競技壁と区別できません。設置したミラー・競技床・照明で黒壁と緑床のLAB値を測定してください。`MIRROR_CENTER`、`MIRROR_RING`、`GROUND_POINTS` が未設定の場合、床から境界への走査結果は表示されません。

`wall_only.py` は初期設定でミラーなし（`USE_MIRROR = False`）です。負荷を抑えるため黒領域の四隅と面積から四角形らしさを判定します。黒い家具・影も候補になり得ます。ミラー装着時は `USE_MIRROR = True` に変更し、上記のミラー校正を行います。床から境界への走査を診断したいときのみ `SHOW_FIELD_EDGES = True` にしてください。シリアルログは約1秒間隔でFPSを表示し、UART送信は200 ms間隔です。競技用スクリプトの壁回避には反映されません。
