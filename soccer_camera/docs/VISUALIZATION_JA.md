# 認識結果と移動方向の可視化

表示専用です。走行判断には何も戻しません。**実機では未確認です。**

## 配線（MAIN → カメラ）

回路図 `ir&main/ir.kicad_sch`（2026-11-16版、リポジトリ外）のネットリストでは、カメラ用コネクタ J6 は次のとおりです。MAINは U17（RP2354A、RS485のDEがGP8、BNOがGP4/5）で、現行ファームウェアのピン設定と一致します。

| J6 | ネット | MAIN | OpenMV H7 Plus |
|---|---|---|---|
| 1 | `cam_tx` | GP2（MAINが送信） | P5（UART3 RX）← **今回新しく使う線** |
| 2 | `cam_rx` | GP3（MAINが受信） | P4（UART3 TX）　従来の線 |
| 3 | GND | GND | GND |

- 基板上は双方向です。**ハーネスでJ6の1番がP5につながっているかは未確認**です。電源を切って導通を確認してください。つながっていなければ画面に `MAIN: NO DATA` と出ます（その場合も認識と走行は変わりません）。J6の端子の向きは現物で確認してください。
- 別の回路図 `soccer_main/main.kicad_sch` はカメラがGP12/13で、現行ファームウェアと合いません。使う基板がこちらなら通信しません。

## 通信方式

| 区間 | 内容 |
|---|---|
| カメラ → MAIN | 変更なし（拡張通信32バイト、115200bps） |
| MAIN → カメラ | 19バイト、100msごと、同じUART・同じ速度（初期設定は115200bps） |

`0-1` `D7 7D`、`2` 版1、`3` 長さ19、`4` 連番、`5` フラグ（新経路／IR通信OK／カメラ通信OK／ボール検出中／停止操作中）、`6-7` IRボール方位（なしは`0xFFFF`）、`8` IR信頼度（旧経路は255＝なし）、`9` IRの経過10ms単位、`10-11` 移動指令方向、`12` 指令出力、`13` 旋回+128、`14` 戦術、`15` 姿勢モード、`16` BNO（0無効／1データなし／2使用中）、`17-18` CRC16-CCITT。

MAINは送信FIFOに空きがある分だけ書くので、送信で制御ループは待ちません。前の送信が残っている間の新しいデータは捨てます。

**古いIR情報は出しません。** MAINは直近のIR応答で検出中の場合だけ方位を送り（予測や記憶は送りません）、カメラは「MAINでの経過＋受信後の経過」が200msを超えたボールと、400ms以上更新のないMAIN情報を表示しません。IRで分かるのは方向だけなので、矢印の長さは固定で距離を表しません。

## OpenMV IDEでの使い方

1. OpenMVに `goal_wall_navigation.py`（`main.py`）、`camera_calibration.py`、`competition_vision.py`、`visualize.py` をコピーする。
2. `camera_calibration.py` で `PROTOCOL = 2`、`VISUALIZE = True` にする。
3. `main.py` を実行してフレームバッファを見る。**競技前に `VISUALIZE = False`、`GOAL_DEBUG = False` に戻す。**

画面表示は拡張通信（`PROTOCOL = 2`）用です。`PROTOCOL = 1` では以前の簡易表示になります。

| 色 | 意味 |
|---|---|
| 赤い線 | 機体の正面（`FRONT_DEG`） |
| 黄・青の枠、十字、数字 | 合格したゴール候補と中心、方位（度） |
| オレンジの矢印 | IRのボール方向（MAINから） |
| 緑の太い矢印 | MAINの移動指令方向（出力0のときは出ない） |
| 白い十字 | 検出した白線の点 |
| 水色の短い線（リング外周） | 安全な移動方向（16方向） |

文字は黒い下地付きで、ミラー映像の外側にまとめています（QVGA）。矢印の先の `F` は正面、`B` はボール、`M` は移動指令です。

| 位置 | 内容 |
|---|---|
| 左列・上 | `FPS`、床の状態（`FLOOR OK`／`SLOW`／`NO FLOOR`） |
| 左列・中（橙） | `BALL(IR)` の方位と信頼度 `conf` |
| 左列・下（緑） | `MOVE` の指令方向（出力0は `STOP`）、`pwr` 出力、`turn` 旋回、停止操作中は `HOLD` |
| 右列 | `YELLOW`／`BLUE` の追跡方位と信頼度 `c`、検索結果（緑 `SEEN`、赤 `NOCOLOR`／`NG 理由`） |
| 下段 | 戦術 / 姿勢モード、`IR`・`CAM`・`BNO`（緑は正常、赤は異常、灰色はBNO未使用） |

候補の枠と除外理由は数フレームに1回更新します（右列の追跡値は認識の周期どおり）。

## FRONT_DEG の校正

初期値を **86.0**（画像からの推定。以前は297.0）に変えました。**この値は白線回避の方向にも使います。違っていると白線の方へ逃げる恐れがあるので、床で走らせる前に必ず確認してください。**

1. 車輪を浮かせ、`VISUALIZE = True` にする。
2. 機体の真正面に目印を置き、赤い線が目印を指すように `FRONT_DEG` を変える（画像の上が0°、時計回り）。
3. 目印を機体の右に置き、`GOAL_DEBUG` かゴール色の目印で方位が約90°になることを確認する。270°なら `CLOCKWISE` を反転する。

## ゴールが認識できないときの診断

`GOAL_DEBUG = True`（`VISUALIZE` はTrueでもFalseでも可）にすると、約10フレームごとにリングの中心・半径と、色の候補を多い順に出力します。例：`YELLOW TURF px=210 r=61 w=24deg asp=1.90 den=0.55 at=12`

| 表示 | 意味 | 確認すること |
|---|---|---|
| `NO COLOR` | 色の候補がない | LABしきい値（`YELLOW`／`BLUE`）、露出。`debug_thresholds.py` で実物の色を測る |
| `SMALL` | 画素数不足 | `*_MIN_PIXELS`。スタート位置では小さく写る |
| `RING` | ミラーのリングの外か内側 | `MIRROR_CENTER`／`MIRROR_RING`。遠いゴールは外周寄りに写る |
| `EMPTY` | 大きさが無効、または中心上 | |
| `WIDTH` | 角度幅が範囲外 | `GOAL_MIN_WIDTH_DEG`／`GOAL_MAX_WIDTH_DEG` |
| `TALL` | 縦長すぎる | `GOAL_MIN_ASPECT`（斜めに写るゴールは値が下がる） |
| `SPARSE` | 色の密度不足 | `GOAL_MIN_DENSITY`、しきい値の取りこぼし |
| `TURF` | 外側に緑床が見える | 床上の物体と判定。本物のゴールなら緑のしきい値とリング外周を確認 |
| `OK` | 合格 | 画面上部の信頼度が40以上でMAINが使う |

診断は画面全体を調べるので遅くなります。浮かせた状態か手で持って使ってください。診断の追加で判定の結果は変わりません。

## USBでの代替表示（PC）

UARTの戻り線が使えない場合に使います。

1. MAINをUSBでPCにつなぎ、Chrome か Edge で `tools/viewer.html` を開く。
2. 「MAINに接続」でMAINのポートを選ぶ（Arduinoのシリアルモニタは閉じる）。
3. ページが `v` を送り、MAINが100msごとに `VIZ,...` の行を出します。もう一度 `v` で止まります。

表示はボール（IR）、移動指令、両ゴール（MAINが受信した値）と数値です。白線と画像は出ません。500ms以上古いデータ、200msを超えたボールは表示しません。

| 目的 | 設定 |
|---|---|

| ゴール診断 | `GOAL_DEBUG` |

## 性能

競技設定（`VISUALIZE = False`、`GOAL_DEBUG = False`）ではカメラは `visualize.py` を読み込まず、追加の検索や描画をしません。MAINは100msごとに19バイトを非ブロッキングで送るだけです。

認識結果を変えずに行った高速化（PCで400フレーム分の出力が変更前と完全一致）：

| 処理 | 内容 | PC上の比（CPython、参考値） |
|---|---|---|
| 床・白線の走査 | 同じ色の分類を表引き（最大2048色）、関数呼び出しを削減、`@micropython.native` | 約1.2倍 |
| 白線の方向判定 | 16方向の確認範囲を起動時に1回だけ計算 | 約3倍 |
| 通信CRC | 256要素の表引き | 約9倍 |
| 画面表示 | 候補検索を毎フレームから4フレーム（診断は3フレーム）に1回、診断の出力は約1秒ごと | 未計測 |

**カメラ実機のFPSは未計測です。** PCの比はそのまま実機の比にはなりません。`@micropython.native` は実機で起動することを確認してください（起動時にエラーが出る場合はその行を削除します）。

FPSの上限は露光時間で決まります。`EXPOSURE_US = 45000`（45ms）では**約22fpsを超えられません**。さらに上げるには露光を短くして `GAIN_DB` を上げ、色のしきい値を測り直す必要があるため、変更していません。表示ON、特に `GOAL_DEBUG` は大きく遅くなります。フレーム間隔が200msを超えるとMAINはカメラ通信断として停止します。OpenMV IDEのフレームバッファ表示も止めると速くなる場合があります。2秒ごとの `fps= capture_ms= line_ms=` で、時間がどこで使われているかを確認できます。
