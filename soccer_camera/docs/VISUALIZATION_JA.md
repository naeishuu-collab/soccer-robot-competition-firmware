## 配線（MAIN → カメラ）

回路図 `ir&main/ir.kicad_sch`（2026-11-16版、リポジトリ外）のネットリストでは、カメラ用コネクタ J6 は次のとおりです。MAINは U17（RP2354A、RS485のDEがGP8、BNOがGP4/5）で、現行ファームウェアのピン設定と一致します。

| J6 | ネット | MAIN | OpenMV H7 Plus |
|---|---|---|---|
| 1 | `cam_tx` | GP2（MAINが送信） | P5（UART3 RX）← **今回新しく使う線** |
| 2 | `cam_rx` | GP3（MAINが受信） | P4（UART3 TX）　従来の線 |
| 3 | GND | GND | GND |

- 基板上は双方向です。**ハーネスでJ6の1番がP5につながっているかは未確認**です。電源を切って導通を確認してください。つながっていなければ画面に `MAIN: NO DATA` と出ます（その場合も認識と走行は変わりません）。J6の端子の向きは現物で確認してください。
- 別の回路図 `soccer_main/main.kicad_sch` はカメラがGP12/13で、現行ファームウェアと合いません。使う基板がこちらなら通信しません。

## 通信方式

| 区間 | 内容 |
|---|---|
| カメラ → MAIN | 変更なし（拡張通信32バイト、115200bps） |
| MAIN → カメラ | 19バイト、100msごと、同じUART・同じ速度（初期設定は115200bps） |

`0-1` `D7 7D`、`2` 版1、`3` 長さ19、`4` 連番、`5` フラグ（新経路／IR通信OK／カメラ通信OK／ボール検出中／停止操作中）、`6-7` IRボール方位（なしは`0xFFFF`）、`8` IR信頼度（旧経路は255＝なし）、`9` IRの経過10ms単位、`10-11` 移動指令方向、`12` 指令出力、`13` 旋回+128、`14` 戦術、`15` 姿勢モード、`16` BNO（0無効／1データなし／2使用中）、`17-18` CRC16-CCITT。

MAINは送信FIFOに空きがある分だけ書くので、送信で制御ループは待ちません。前の送信が残っている間の新しいデータは捨てます。

**古いIR情報は出しません。** MAINは直近のIR応答で検出中の場合だけ方位を送り（予測や記憶は送りません）、カメラは「MAINでの経過＋受信後の経過」が200msを超えたボールと、400ms以上更新のないMAIN情報を表示しません。IRで分かるのは方向だけなので、矢印の長さは固定で距離を表しません。

## OpenMV IDEでの使い方

1. OpenMVに `goal_wall_navigation.py`（`main.py`）、`camera_calibration.py`、`competition_vision.py`、`fast_scan.py`、`visualize.py` をコピーする。
2. `camera_calibration.py` で `PROTOCOL = 2`、`VISUALIZE = True` にする。
3. `main.py` を実行してフレームバッファを見る。**競技前に `VISUALIZE = False`、`GOAL_DEBUG = False` に戻す。**

画面表示は拡張通信（`PROTOCOL = 2`）用です。`PROTOCOL = 1` では以前の簡易表示になります。

| 色 | 意味 |
|---|---|
| 赤い線 | 機体の正面（`FRONT_DEG`） |
| 黄・青の枠、十字、数字 | 合格したゴール候補と中心、方位（度） |
| オレンジの矢印 | IRのボール方向（MAINから） |
| 緑の太い矢印 | MAINの移動指令方向（出力0のときは出ない） |
| 白い十字 | 検出した白線の点 |
| 水色の短い線（リング外周） | 安全な移動方向（16方向） |

文字は黒い下地付きで、ミラー映像の外側にまとめています（QVGA）。矢印の先の `F` は正面、`B` はボール、`M` は移動指令です。

| 位置 | 内容 |
|---|---|
| 左列・上 | `FPS`、床の状態（`FLOOR OK`／`SLOW`／`NO FLOOR`） |
| 左列・中（橙） | `BALL(IR)` の方位と信頼度 `conf` |
| 左列・下（緑） | `MOVE` の指令方向（出力0は `STOP`）、`pwr` 出力、`turn` 旋回、停止操作中は `HOLD` |
| 右列 | `YELLOW`／`BLUE` の追跡方位と信頼度 `c`、検索結果（緑 `SEEN`、赤 `NOCOLOR`／`NG 理由`） |
| 下段 | 戦術 / 姿勢モード、`IR`・`CAM`・`BNO`（緑は正常、赤は異常、灰色はBNO未使用） |

候補の枠と除外理由は数フレームに1回更新します（右列の追跡値は認識の周期どおり）。

## FRONT_DEG の校正

初期値を **86.0**（画像からの推定。以前は297.0）に変えました。**この値は白線回避の方向にも使います。違っていると白線の方へ逃げる恐れがあるので、床で走らせる前に必ず確認してください。**

1. 車輪を浮かせ、`VISUALIZE = True` にする。
2. 機体の真正面に目印を置き、赤い線が目印を指すように `FRONT_DEG` を変える（画像の上が0°、時計回り）。
3. 目印を機体の右に置き、`GOAL_DEBUG` かゴール色の目印で方位が約90°になることを確認する。270°なら `CLOCKWISE` を反転する。

## ゴールが認識できないときの診断

`GOAL_DEBUG = True`（`VISUALIZE` はTrueでもFalseでも可）にすると、約10フレームごとにリングの中心・半径と、色の候補を多い順に出力します。例：`YELLOW TURF px=210 r=61 w=24deg asp=1.90 den=0.55 at=12`

| 表示 | 意味 | 確認すること |
|---|---|---|
| `NO COLOR` | 色の候補がない | LABしきい値（`YELLOW`／`BLUE`）、露出。`debug_thresholds.py` で実物の色を測る |
| `SMALL` | 画素数不足 | `*_MIN_PIXELS`。スタート位置では小さく写る |
| `RING` | ミラーのリングの外か内側 | `MIRROR_CENTER`／`MIRROR_RING`。遠いゴールは外周寄りに写る |
| `EMPTY` | 大きさが無効、または中心上 | |
| `WIDTH` | 角度幅が範囲外 | `GOAL_MIN_WIDTH_DEG`／`GOAL_MAX_WIDTH_DEG` |
| `TALL` | 縦長すぎる | `GOAL_MIN_ASPECT`（斜めに写るゴールは値が下がる） |
| `SPARSE` | 色の密度不足 | `GOAL_MIN_DENSITY`、しきい値の取りこぼし |
| `TURF` | 外側に緑床が見える | 床上の物体と判定。本物のゴールなら緑のしきい値とリング外周を確認 |
| `OK` | 合格 | 画面上部の信頼度が40以上でMAINが使う |

診断は画面全体を調べるので遅くなります。浮かせた状態か手で持って使ってください。診断の追加で判定の結果は変わりません。

## USBでの代替表示（PC）

UARTの戻り線が使えない場合に使います。

1. MAINをUSBでPCにつなぎ、Chrome か Edge で `tools/viewer.html` を開く。
2. 「MAINに接続」でMAINのポートを選ぶ（Arduinoのシリアルモニタは閉じる）。
3. ページが `v` を送り、MAINが100msごとに `VIZ,...` の行を出します。もう一度 `v` で止まります。

表示はボール（IR）、移動指令、両ゴール（MAINが受信した値）と数値です。白線と画像は出ません。500ms以上古いデータ、200msを超えたボールは表示しません。

## 性能

### 実機の測定（2026-11-27、利用者のログ。コミット5d2ee28まで）

FPS 2.9〜16.4、`capture_ms` 4〜5、`line_ms` 43〜324（最大669）、`NOFLOOR`・`SLOW` が頻発、黄ゴール未検出、青ゴールは不安定。表示設定は記録されていません。

### 原因（コードの監査。実機では未確認）

| 現象 | 原因 |
|---|---|
| `line_ms` が大きく、ばらつく | 床の走査が1フレームに568点をPythonで読み、画素ごとに色のタプルを確保。時間のばらつきはGC（不要メモリの回収）が重なったためと**推定** |
| `SLOW` | 撮像＋走査＋認識が100msを超えると出る。上の走査時間が原因 |
| `NOFLOOR` | 速さではなく認識の結果。緑床か白線が見える方位が12未満。または校正の設定不備。机の上など緑の床がない場所でも出る |
| 黄ゴール未検出・青が不安定 | 実画像がないため未特定。`GOAL_DEBUG` の除外理由が必要 |

### 高速化の内容

| 内容 | 判定への影響 |
|---|---|
| `fast_scan.py`：起動時に全65536色の分類表を作り、viper関数が画像バッファを直接読む。画素ごとの確保なし | なし。起動時に実フレーム3枚で従来版と全点一致した場合だけ使う。違えば自動で従来版。PCでは乱数の床3000枚で一致 |
| 画面表示は認識が調べた候補をそのまま表示（`GOAL_DEBUG` 以外は追加検索なし） | なし。表示する候補は認識と同じ範囲になる |
| 拡張通信で使わない旧判定（`decide_navigation`）を省略 | なし |
| ゴール検索は色ごとに80ms以上の間隔 | 白線のループが速くなっても検索回数は増えない |
| 白線の退避解除は2フレームに加え100ms以上 | FPSが上がっても早く解除しない（安全側の追加） |

安全停止の条件とタイムアウト（100ms、MAINの200ms）は変えていません。通信形式も同じです。

### 推定と限界

- **実機のFPSは未計測です。** viperの走査は数ms以下になると**推定**しますが、確認していません。viperと `img.bytearray()` が本体で使えない場合は `fast scan OFF: 理由` と表示して従来の速度になります。
- **25FPSと40FPSは、今の露光設定では保証できません。** `EXPOSURE_US = 45000`（45ms）は1フレームの撮像が45ms以上かかり、**約22FPSが上限**です。25FPSには露光35ms以下、40FPSには22ms程度以下にして `GAIN_DB` を上げ、緑・白・黄・青のしきい値を測り直す必要があります。認識に影響するので変更していません。
- 起動時に分類表を作るため、数秒（推定）余分にかかります。その間MAINはカメラ通信がないので停止します。
- `VISUALIZE = False`、`GOAL_DEBUG = False` が競技の標準です。`GOAL_DEBUG` は画面全体を追加で検索するので大きく遅くなります。

### 計測の読み方（2秒ごと、拡張通信のみ）

```
fps=.. capture_ms=.. line_ms=..
ms avg/max/p95 capture=a/m/p scan=.. vision=.. uart=.. show=.. total=..
{'YELLOW': .., 'BLUE': .., 'pose': ..} V3 OK|SLOW|NOFLOOR mask=....
floor setup-ok visible=.. lines=.. near-samples green=.. white=.. black=.. other=..
```

`ms` は平均／最大／95%値（直近最大128フレーム）。`scan` 床と白線、`vision` ゴール認識・判定・パケット作成、`show` 表示、`total` 1周の時間。`NOFLOOR` のときは `floor` 行を見ます。`setup-ok` 以外は表示された校正項目を直します。`other` や `black` が多ければ緑のしきい値か露出、ミラー中心・半径、`GROUND_POINTS` を確認します。

## 床面認識の全体条件の解除（`FORCE_FLOOR_OK`）

`camera_calibration.py` の設定です。リポジトリの値は `True` です。行がない場合は従来どおり（`False`）です。

| 項目 | `True` | `False` |
|---|---|---|
| 緑床か白線が見える方位が24中12未満 | 停止しない（画面 `FLOOR OK (FORCED)`） | `NOFLOOR` で停止 |
| 床が見えない方向（その方向の±30°） | **閉じたまま** | 閉じる |
| 床がどこにも見えない | **安全方向が空なので停止**（MAINの表示は `no safe direction`） | 停止 |
| 校正設定の異常（画面寸法・ミラー・`GROUND_POINTS`） | 停止 | 停止 |
| 処理が100msを超える | 停止／直前の白線データを最大150ms | 同じ |
| 白線の検出・退避 | 同じ | 同じ |

実際の認識結果は2秒ごとの `floor` 行に残ります（`actual=OK|NOFLOOR observed=n/24 forced=0|1 mask=....`）。MAIN・IR・MOTORの変更はありません。

**注意**：解除すると、床の認識がほとんど失敗している状態でも、緑に見えた方向があれば走ります。緑に似た色を床と誤認すると、確認の機会が減ります。`mask=0000` で止まる場合は、緑のしきい値か露出、ミラー中心・半径を直してください。このスイッチでは動くようになりません。

## OpenMVへの書き込み手順

1. OpenMV IDEを停止状態にし、本体のドライブ（OPENMV）にある `*.py` をPCにバックアップする。
2. 次のファイルをドライブにコピーする：`competition_vision.py`、`fast_scan.py`（新規）、`visualize.py`、`goal_wall_navigation.py`。
3. `camera_calibration.py` は本体の調整値を残す。`VISUALIZE` と `GOAL_DEBUG` を `False` にする（確認中は `VISUALIZE = True` 可）。
4. IDEで `goal_wall_navigation.py` を開いて実行し、`fast scan ON` が出ることと計測行を確認する。
5. 競技で電源投入と同時に動かすには、`goal_wall_navigation.py` の内容を `main.py` として保存する。**MAINとMOTORの電源が入っていると走り出すので、車輪を浮かせて確認する。**
