# ファームウェア動作ガイド

この説明は `soccer_camera` と `soccer_ir_main_line` の現在のソースに対応します。両方とも `AUTO IR` では故障中のLINE基板を照会しません。実機試験済みのchase.zipから取り込んだ部分も、統合後の実機動作は未確認です。

## どのファイルをどの基板に書くか

| ファイル | 書き込み先 | 仕事 |
|---|---|---|
| `main/main.ino` | MAIN | 入力をまとめ、走行・停止・キックを決める |
| `ir/ir.ino` | IR | 12個の赤外線受信器からボールの方向と相対信号を計算する |
| `line/line.ino` | LINE | 24入力を読み、白線検出状態をMAINへ返す。現在のAUTO IRでは未使用 |
| `motor/motor.ino` | MOTOR | MAINから受けた4輪PWMをモーターに出し、通信断なら停止する |
| `soccer_camera/openmv/goal_wall_navigation.py` | OpenMV H7 Plus | 全方位ミラー画像から境界とゴールを判断する。OpenMVには `main.py` として保存 |
| `soccer_camera/openmv/camera_calibration.py` | OpenMV | ミラー・床の距離・色・攻撃ゴールの校正値。`main.py` と同じ場所に保存 |

2つの構成はそれぞれ専用のMAIN・IR・MOTORを組み合わせて書き込みます。`common/src/` は共通処理の原本で、その内容は各 `.ino` にも組み込まれています。変更時は原本と各基板のコピーの整合が必要です。

## MAIN：全体の司令塔

1. `setup()` は通信、キッカー出力、BNO055のI2Cなどを準備します。起動時は `AUTO IR` 待ちです。
2. `loop()` はUSB入力、IRとのRS485、BNO055、OpenMV受信を繰り返し、約10 msごとに制御を更新します。IRへは約20 ms間隔で問い合わせます。
3. 新しいIR応答から、ボールの有無・方位・相対信号を取得します。応答が古くなると追跡しません。
4. `IrTestController` はIR方位を前後・左右の移動に変換します。車輪値は `omniKinematics` で4輪へ割り当て、AUTO IRの各輪PWMは180までです。非ゼロ指令の最大車輪値を150以上とし、他輪は比率を維持します。
5. モーター指令はRS485で送ります。停止指令は通常の走行指令より優先します。USBの `S` は停止です。

自動ARMは行いません。`AUTO IR`、その後、新鮮なボール検出中に `ARM IR` を送ります。ボールを見失った際は停止しますが、ARMが残っていれば再検出で自動再開します。

### カメラ版

校正済みカメラの新しいデータとIRの新しい応答が必要です。カメラが境界回避を指示したら追跡やキックより優先します。画像の判定がWAIT、または通信が古いときは停止します。

`kOpenMvCloseIrSignal` はキック可能な近さの目安です。0の間も追跡・回避は行いますが、近接判定が成立しないためゴール整列とキックは行いません。測定後はボールが正面かつ近く、攻撃ゴールが整列し、回避中でない場合にキックを要求します。

### カメラなし版

IR方位に沿って平行移動し、ボール消失やIR応答の期限切れで停止します。白線・壁・ゴールは認識できません。`kIrKickCloseSignal` は初期値0でキック無効です。0以外に設定すると、新鮮なIR・近接信号・正面±5°を条件にキックしますが、ゴールの向きは確認できません。

## IR：ボール方向の計算

`sampleSensors()` が12入力を2 ms読み、受光した回数を数えます。`calculateDirection()` はセンサーごとの向きを重みとして合成し、検出数が3未満ならボールなしにします。GPIO18を0°、GPIO19を330°、GPIO20を300°とし、以降も30°刻みで計算します。180°補正は行いません。

`sendIRResponse()` は方向と相対信号をMAINに返します。相対信号は検出履歴から求める値で、cm単位の距離ではありません。キック近接しきい値は競技球と機体で実測する必要があります。

## LINE：現在は使わない

LINE基板は24チャンネルを読み、故障した6チャンネルを除外して検出・方向を計算します。要求を受けた場合はCRC付きの状態を返します。ただし `AUTO IR` はLINEを照会しないため、この基板を接続・書き込みしても白線回避には使われません。通常AUTOの安全ゲートは未確認設定により閉じています。

## OpenMV：白線・壁・ゴール

`camera_calibration.py` で画像サイズ、ミラー中心と範囲、正面方向、床上の距離と画像半径の対応、床・線・ゴールの色、攻撃ゴール色を設定します。初期状態では未設定なので、競技用に校正する必要があります。

`goal_wall_navigation.py` は床を24方向に走査し、緑床から白線や黒壁への変化を探します。近い境界から離れる指令を出し、見える床が不足する場合はWAITを送ります。ゴール色の位置が安定して見えたときはゴール方向もMAINへ送ります。距離、色、18 cmの回避設定は現場の照明・ミラー・機体で確認が必要です。白線の種類や遮られた境界は確実に判別できません。

## MOTOR：4輪を動かす

MAINの4輪指令を受け、値とチェックサムを検査します。内部の速度指令は10 msごとに5ずつ変化し、出力時は各輪の非ゼロPWMを120〜200に制限します。車輪ごとの下限制限により移動方向が変わる場合があります。逆方向への切り替えには200 msの停止時間を入れます。停止指令や100 msの通信期限切れでは停止します。4番目の出力ピンはchase.zipに合わせIN1=GPIO8、IN2=GPIO9です。

## 試験上の注意

LINEなしのカメラなし版は境界が分かりません。カメラ版も未校正時や遮蔽時の白線検出は保証できません。キッカーを無効にし車輪を浮かせ、MOTOR電源を直ちに遮断できる状態で、各輪・IR方向・停止・通信断を確認してから次へ進みます。AUTO IRには確認済みのMAIN物理非常停止入力がありません。
