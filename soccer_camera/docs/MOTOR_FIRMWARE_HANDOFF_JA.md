# MOTORファームウェア引き渡し

## 現在の前提

- ユーザー指定のsoccer.zipを完成版のMOTOR親基板資料として扱う。親基板はRP2354AでPWM/RS485ネットを示し、ユーザー報告GPIO表と一致する。
- ZIP子基板はIR4427系/MOSFETで、ユーザーが実機確認したTB67H450×4とは異なる。コードの真理値表はTB67H450のユーザー確認値に基づき、ZIP子基板回路へは適用しない。
- ユーザーが実機で確認したのはTB67H450×4の正転・逆転・停止・ブレーキ。基準配列はIN1={6,12,11,8}、IN2={7,13,10,9}、RS485はTX0/RX1/EN2。RS485通信は未検証。4輪合成、車輪極性・ローラー向き、ARM/E-stop、電源定格も未確認。

根拠: [MOTOR_REVISION_DIFF_JA.md](MOTOR_REVISION_DIFF_JA.md)。
確認手順: [MOTOR_HARDWARE_TEST_JA.md](MOTOR_HARDWARE_TEST_JA.md)。

## ソフトウェアの状態

`main/main.ino`は12 byte MOTORフレームを送信し、`motor/motor.ino`はその受信・検証、300ms期限切れ、4輪ごとのランプ、200ms逆転待機、安全ゲート、TB67H450出力表を実装します。

- フレーム: `AA 04 [int16 little-endian ×4] XOR 55`。値は -255..255、256=ブレーキ。MOTOR側で形式・値域・XOR・終端・8msの部分フレーム期限を検査
- TX/RX/DE候補は基準コードからGP0/1/2、UART候補は115200bps。ピン設定をコードへ入れた段階で、実配線・終端・DE動作・通信成功は未検証
- PWM GPIOはIN1={6,12,11,8}、IN2={7,13,10,9}。20kHz、範囲255、Duty上限128。4動作の論理表はユーザー確認済み
- 車輪位置角・ローラー方向・極性の設定フラグはfalse。MOTORハードウェア設定もfalse
- ARM/E-stop/FAULT解除ピン未割当て、入力バイアス未確認。MAIN競技ARMもfalse
- 実PWM出力なし。現状はコード実装・ビルドまでで、実機を動かせる状態とは判定しない

Arduino-Picoで4スケッチのコンパイルは成功しました。ホストC++テスト2本もコンパイルしました。test_coreは一度実行した際に54ケース中2件の期待値不一致が出たため修正しましたが、その後の実行はWindows Application Controlに拒否され、修正後の最終結果は未確認です。RS485通信や実機停止を成功と報告しません。

## 次の担当者に必要な入力

1. 実機MCU刻印とZIP親基板RP2354Aネットの電源OFF導通記録。
2. TB67H450×4の実搭載型番、各ドライバー入力とJ1/J2/J6/J7の対応。
3. RS485 TX/RX/DE/A/B、/RE、終端、バイアスの導通・実通信記録。
4. ARM/E-stop/FAULT解除、入力バイアス、CPU停止時の独立電源遮断。
5. 4輪のローラー向き、正転極性、実測した合成方向と低速挙動。
6. 安全条件を確認してからの通信期限・停止時間測定。

設計版と導通測定をレビューするまでBoardConfigを有効化しない。旧版の値から推測して埋めない。接続・駆動・書き込みは行っていない.
