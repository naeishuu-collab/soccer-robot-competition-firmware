## 2. 何が初期状態で変わるか

### 新機能（初期状態はOFF）

| 切替 | 場所 | 初期値 |
|---|---|---|
| 車輪モデル・始動補助 | `motor/motor.ino` の `ROBOT_UPGRADE` | 0 |

### 安全のため初期状態でも変わる動作

| 場面 | 以前 | 今回 |
|---|---|---|
| カメラの床認識ができない・退避先がない | 全方向を許可して走行 | `WAIT` を送り停止 |
| MAINが `mode=0` を受信 | ボール方向へ走行 | 停止 |
| ボールを見失う | 最後の方向へ無期限に走行 | ロック失効後も含め最後の検出から500msで停止 |
| 起動直後でボール未検出 | 前進 | 停止 |
| 白線回避の出力（MAIN `AVOID_POWER`） | 128 | 160（停止して退避できないのを防ぐ） |

そのため、**床の校正が悪いと以前より停止しやすくなります。** 白線の上で退避先が確認できない場合も停止したままになります。

MAIN・IR・MOTORには診断コマンドも追加しました（入力しなければ以前と同じ）。

## 3. 監査で見つけた問題

1. 旧ミキサーは出力160で、回っている車輪がすべて160になる。方位30°を指示すると4輪が160となり、**正面(0°)へ進む計算**になる（PC検証）。
2. 旧ミキサーに旋回補正を足すと145など持続下限未満が出る（BNO無効の現在は発生しない）。
3. 回避出力128は走行下限160より低い。
4. 床が認識できない・退避先がない場合に全方向許可（カメラ）、`mode=0` でも走行（MAIN）。
5. ボール消失後に最後の走行方向（白線回避の方向を含む）へ走り続ける。
6. IR応答にCRCがない。信頼度もない。
7. ゴール・ボール認識は画面表示だけで使われていた。
8. 加速の確認：旧コードは停止から `min(指令,160)` を**すぐ**出力します。「0から160まで約320ms」は現行コードでは起きません。5/10msのランプは160→210で約100msです。

## 4. モーター制御（`motor/motor_logic.h`）

### 新旧比較（PCで計算したPWM。並びはチャンネル0〜3）

| 指令（方位, 出力, 旋回） | 旧 | 新 | 新の方向誤差 |
|---|---|---|---|
| 0, 160, 0 | 160,160,160,160 | 176,176,176,176 | 0° |
| 30, 160, 0 | 160,160,160,160（実質0°） | 210,210,0,0（45°） | 15° |
| 45, 160, 0 | 160,160,0,0 | 176,176,0,0 | 0° |
| 0, 120, 0 | 120×4 | 160×4 | 0° |
| 0, 160, 15 | 175,145,175,145 | 188,160,188,160 | 0° |
| 90, 128, 0 | ±128 | ±160 | 0° |

新方式では `出力` はPWMではなく**速度要求（210＝最大）**です。PWMは表から逆算します。

### 仕組み

- 並進と旋回を合成し、**全輪共通の倍率**で正規化する。
- 小さい車輪が持続下限を下回る場合は、まず全体を上げる（最大PWM210まで）。
- それでも下回る車輪は「停止」か「持続下限」の全組合せ（最大16）を比べ、方向誤差・不要な旋回・車輪同士の打ち消し・切替（ヒステリシス）が最小のものを選ぶ。
- 方向誤差が30°を超える場合は全輪停止し `feasible=0`。旋回を足すと実現できない場合は旋回を捨てて並進する。
- 実現できる方向は限られます。**中間角度は最大約23°ずれます。** 回転比が保てるのは、小さい車輪も下限以上にできる角度（45°の倍数の近くや、基本方向から約10°以内）だけです。
- 始動補助：80ms以上止まっていた車輪の開始時に `startDuty`(180) を `boostMs`(60ms、上限150ms) 出し、その後は運転PWMへ。
- 逆転：どれか1輪でも逆転する場合は4輪とも停止し、200ms待つ。始動補助は逆転待ちを迂回しない。
- 加速は5/10ms、減速は10/10ms。走行中に持続下限未満へは下げない。
- 通信断100msで停止。

### 方式の比較

| 方式 | 採否 |
|---|---|
| 全輪共通スケーリング | 採用（最初に適用） |
| 実測PWM表の逆変換 | 採用（表は仮値） |
| ゼロ付近の停止＋ヒステリシス／実現可能ベクトルへの再計算 | 採用（全組合せ探索） |
| 間欠駆動 | **未実装**（振動・発熱・遅れの懸念。方向誤差を表示する） |

### 実機で必ず測る仮値（`kWheels`）

車輪ごと・正逆ごと：`startDuty` 180、`holdDuty` 160、`gainPermille` 1000、`table` {160:650, 185:830, 210:1000}。車輪ごと：`degrees`、`polarity`、`maxDuty` 210、`accelStep`、`decelStep`、`boostMs`。`normalDuty` は記録用でコードは使いません。**160で全条件で回る保証はありません。**

## 5. 白線回避

- 通信v1：停止条件を修正（上の表）。8方向は従来どおり。
- 通信v2（`competition_vision.py` の `LineGuard`）：16方向マスク、複数の線の同時処理、コーナーの斜め退避、`LINE_BLOCK_CM`(35cm)で接近方向を早めに閉じる、`LINE_CLEARANCE_CM`(25cm)で退避、解除は+5cmかつ2フレーム、退避方向の維持。退避先がなければマスク0＝停止。
- MAINは線の近くでは、前後左右・斜め45°か、両隣も開いている方向だけを選びます。
- 回避後のボール再捕捉は、通常の追跡状態に戻ることで行います。

回避距離の決め方（自動計算はしません。測って設定します）：

`回避距離(ミラー軸から) ≥ カメラから機体端まで ＋ 速度×(画像処理＋通信＋制御の遅れ) ＋ 停止距離 ＋ 速度×逆転待ち0.2s ＋ 余裕`

逆転待ちの間は停止（惰性）なので、余裕は大きめにします。

## 6. IR（`ir/ir_logic.h`、ポーリング命令 `0x02`）

サンプル数で正規化（‰）、センサー別ゲイン、ピークの20%未満は反射・雑音として除外、ベクトル集中度の信頼度、変化量で強さが変わる円周EMA、3回未検出で追跡リセット、固着・断線センサーの約3秒後の除外と隣接値での補間、復帰判定。MAIN側で45°を超える急変は2回一致で採用します。検出強度は距離に変換しません。

従来の命令 `0x01` の処理は変えていません。実機で `kGain`、`kReflectionRatio`、`kFullLevel` を調整します。**2026年の公式ボールは42mmに変わっており、検出量が以前と違う可能性があります。**

USBで `v` を送ると12個の値、フィルター前後の角度、信頼度、異常ビットを表示します。MAINが接続されていない場合も表示します。

## 7. 姿勢制御（BNO055故障時を含む）

| モード | 条件 | 動作 |
|---|---|---|
| `VISION_ONLY`（主運用） | 両ゴールからの推定が5回連続 | 攻撃方向を向くPD補正 |
| `VISION_ONLY`（ゴール相対） | ゴール1つだけ | 位置合わせ・攻撃中のみ、半分のゲインでゴールを向く。方位は作らない |
| `BNO_ONLY` | BNO正常、視覚推定なし | BNOで補正 |
| `FUSED` | 両方正常 | 相補フィルター（ジャイロ主体、1回1%で視覚へ） |
| `DEGRADED` | どちらもなし | 旋回補正ゼロで制限付きIR追跡（低速） |

- 視覚の方位は「相手ゴール方向ベクトル − 自陣ゴール方向ベクトル」です。コートの中心軸上では正確、それ以外は近似で、両ゴールが反対側に見えないほど信頼度を下げます。**ゴール1つの方位変化は回転角として扱いません。**
- BNO（GPIO4/5、0x28）：`delay` なしで接続確認→IMUPLUS（磁気を使わないのでモーター磁界の影響を避ける）→20ms読出し。無応答でも1秒に1回、最大5msのI2C待ちだけ。ジャイロ校正3のときだけ使用。800°/sを超える急変は除外。10回正常で採用、3回異常か200ms更新なしで解除。
- 復帰時は現在の推定に合わせて基準を決め、急旋回しないようにする。旋回指令は20msごとに最大3しか変化しない。
- 視覚と30°超の差が続く場合：視覚の信頼度70以上なら視覚、そうでなければBNO。
- 電源投入時にBNOだけの場合、**置いた向きを攻撃方向とみなします。**
- DEGRADEDの条件のうち「MOTOR通信が正常」は、MOTOR→MAINの返信がないため**確認できません**（MOTOR側の100ms停止に頼ります）。

仮値：`turnSign`（**浮かせて向き確認が必須**）、Kp 0.5、Kd 0.05、不感帯10°/解除5°、旋回8〜30。

## 8. 認識とセンサー融合

- カメラ（v2）：青・黄ゴールの方位、見かけの角度幅、信頼度、連続性を考慮した候補選択、2つが60°未満なら信頼度半減。ボールは面積・縦横比・充填率。表示の有無に関係なく認識します。
- 距離：`BALL_DISTANCE`、`GOAL_DISTANCE`（床用 `GROUND_POINTS` とは別の表）。空または不正、範囲外は「不明」。**初期は空です。**
- 融合：IRとカメラが30°以内なら信頼度で加重平均して信頼度を上げ、不一致なら信頼度と過去との連続性で選び信頼度を下げる。

## 9. ボール予測と消失時

α-βフィルターで方位と角速度を推定し、80ms先（最大15°）を狙う。BNOがある場合は機体の回転分を補正。

`TRACK`（100ms以内）→ `PREDICT`（信頼度に応じ約0.1〜0.3s）→ `SEARCH`（1.5s。自陣ゴールが見え、**校正済み距離が40cm以上**の場合だけ戻る。それ以外は停止）→ `WAIT`（停止）。

## 10. 戦術と速度

状態：`SEARCH` `APPROACH` `ORBIT` `ALIGN` `ATTACK` `RECOVER` `AVOID_LINE` `SAFE_STOP`

- 攻撃方向：攻撃ゴール → 自陣ゴールの反対 → 推定方位 → 直前1秒の記憶 → 不明。攻撃色は `TARGET_GOAL`。
- ボールとゴールの角度差が15°以内で `ATTACK`（30°を超えるまで継続）、45°未満で `ALIGN`、それ以上は `ORBIT`。距離が不明なら方位だけで回り込む。線に塞がれたら反対回り。
- `ATTACK` が3秒続くと0.4秒下がる。
- 攻撃方向が不明な場合は低速でボールを追います。**このとき自陣ゴール方向へ押す可能性は残ります。**
- 優先順位：通信異常 → 白線 → センサー → モーター実現性（MOTOR側） → 姿勢 → 追跡 → 戦術 → 速度。白線回避中は旋回補正ゼロ。
- 速度要求：低速137（MOTORで持続下限へ）、通常160、遠距離185、攻撃195、回避175。線の近く・低信頼・姿勢誤差45°超は低速。
- キッカーGPIO11はLOWのまま。

## 11. 通信

| 区間 | 内容 |
|---|---|
| OpenMV→MAIN v1 | 9600bps、8バイト、XOR（従来） |
| OpenMV→MAIN v2 | 115200bps、37バイト、`C5 5C` 版2、長さ、連番、CRC16-CCITT |
| MAIN→IR | `A5 5A 01 FE`（従来）／`A5 5A 02 FD`（新） |
| IR→MAIN | `AA 角度2 強度2 55`（従来）／`AB 角度2 強度2 信頼度 異常2 CRC8 55`（新） |
| MAIN→MOTOR | 12バイトDRIVE（変更なし） |

v2の並び：`0-1` ヘッダー、`2` 版、`3` 長さ、`4` 連番、`5` フラグ（認識可／退避／攻撃が青／処理遅れ／攻撃色有効）、`6-7` 方向マスク、`8-9` 退避方位、`10-11` 線の方位、`12` 距離、`13` 線の数、`14-18` ボール（方位2・距離・信頼度・経過10ms単位）、`19-24` 黄（方位2・距離・信頼度・幅・経過）、`25-30` 青、`31-32` 推定方位、`33` その信頼度、`34` 処理ms、`35-36` CRC。不明は角度 `0xFFFF`、値 `255`。

名目の送信時間：v1 約8.3ms、v2 約3.2ms、DRIVE 約1.0ms。PIO UARTの115200bpsは**実機未検証**です。版や速度が合わない場合、MAINは受理せず停止します。RS485の送受信切替、IR応答待ち中は送信しない仕組みは維持しています。

## 15. 初心者向け実機検査手順

**毎回、車輪を浮かせ、すぐ電源を切れる状態で始めます。** 通信が戻ると自動で動きます。

### 段階1：初期設定（すべてOFF）
1. 4基板を書き込む。MAINのシリアル(115200)で `CAM=OK IR=OK` を確認。
2. ボールを前後左右に置き、回転方向を確認。
3. カメラを隠す・ケーブルを抜く・IRを止める → 停止。戻すと再開。
4. ボールを隠す → 約0.5秒で停止。
5. 白線を前後左右に見せ、退避方向を確認。MAINで `d` を送ると停止指令になり、`g` で再開。

### 段階2：モーター測定（MOTORのUSB）
`diag` で診断開始（MAINの指令は無視）。コマンドは最長1.5秒で自動停止します。

| コマンド | 内容 |
|---|---|
| `p 0 f 120` | 車輪0を正転PWM120で0.7秒 |
| `k 0 r 180 150 1500` | 0.1秒だけ180、その後150（持続の確認） |
| `m 30 160 0 1000` | 新モデルで方位30°へ移動（方向誤差を表示） |
| `m 0 0 20` / `m 0 0 -20` | 旋回（左右） |
| `m 90 160 15` | 移動しながら旋回 |
| `s` / `exit` | 停止／終了 |

PWMは120,130,140,150,160,170,180,190,200の順。**回らなければ繰り返さず、通電を続けないこと。** 浮かせた状態と床上を別々に記録します。

| 車輪 | 向き | 浮上:始動 | 浮上:持続 | 床:始動 | 床:持続 | 160/185/210の速度 | 電流 | 発熱 | 電圧 | 停止距離 |
|---|---|---|---|---|---|---|---|---|---|---|
| 0〜3 | f / r | | | | | | | | | |

値を `kWheels` に入れ、極性・前後左右・斜め・中間角度・旋回・逆転待ち・USB以外の通信断停止を確認してから、`ROBOT_UPGRADE 1`（MOTORのみ）にします。MOTORの新モデルは旧MAINと組み合わせられます。

### 段階3：カメラと通信v2
1. 校正（[校正手順](OPENMV_CALIBRATION_JA.md)）。必要なら `BALL_DISTANCE`、`GOAL_DISTANCE` を `((半径px, 距離cm), ...)` で測定。
2. `PROTOCOL = 2` とMAINの `ROBOT_UPGRADE 1`。新IRとMOTORが必要。
3. MAINの2行表示で、`cam` の値（ms）、`err`、`mask`、`mode`、`bno`、状態名と停止理由を確認。
4. 浮かせたまま、ゴールを左右に動かして旋回の向きを確認（逆なら `turnSign = -1`）。
5. 白線（直線・角・2本）、ゴールの誤認識、BNOの抜き差しを確認。
6. 床上は低い場所・手を添えた状態で、停止距離を測ってから `LINE_CLEARANCE_CM` と `LINE_BLOCK_CM` を決めます。

## 16. 競技規則

[RoboCupJunior Soccer Rules 2026](https://robocup-junior.github.io/soccer-rules/master/rules.html)（2026-06-03版）を2026-11-26に要約取得して確認した内容：Infraredは直径22cm・高さ22cm・1500g・ボール保持域1.5cm（6.2.1）、電圧は48V DC以下（1.3.2）、ボール42mm（3.8）、IRを発する部品は禁止（6.2.2）、カメラ数と光学系の制限なし・キック力は検査対象（6.2.3）、審判の合図で開始（2.3）、壁接触かペナルティエリアへの完全進入はアウト（2.8）。

**千葉ノード大会の適用規則は確認できていません。** エントリー版規則など別の数値（1400g、保持域3.0cm、12V）を使う大会もあるため、主催者に確認してください。機体寸法・重量はこの作業では確認していません。

## 17. 大会投入前の残存リスク

- すべて実機未検証。モーターの仮値が合わないと、始動しない・速すぎる・曲がる。
- 安全停止が増え、校正不足だと動かない。
- 全輪同時の逆転待ち200msで追跡と退避が遅れる。
- 低速にできないため、白線手前の惰性が大きい可能性。
- 白線がミラーの死角（約18cmより内側）に入ると検出できない。
- 視覚方位は近似。ゴール誤認識で攻撃方向を誤る可能性。
- 通信v2の処理負荷でフレームが100msを超えると停止する。
- 審判の合図に合わせた開始方法の確認が必要。
