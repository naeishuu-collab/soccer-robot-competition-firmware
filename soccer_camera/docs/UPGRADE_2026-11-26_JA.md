1. 旧ミキサーは出力160で、回っている車輪がすべて160になる。方位30°を指示すると4輪が160となり、**正面(0°)へ進む計算**になる（PC検証）。

8. 加速の確認：旧コードは停止から `min(指令,160)` を**すぐ**出力します。「0から160まで約320ms」は現行コードでは起きません。5/10msのランプは160→210で約100msです。

## 4. モーター制御（`motor/motor_logic.h`）

### 方向誤差の比較（実機確認した配置を基準にしたPC計算。車輪速度はPWMに比例と仮定）

| 指令・出力160 | 動ける方位 | 最大誤差 | 平均誤差 | 備考 |
|---|---|---|---|---|
| 初期設定・修正前 | 222/360 | 55° | 27.7° | 90°と270°は回転のみ、45°刻みの斜めは45°ずれ＋回転 |
| 初期設定・修正後 | 360/360 | 34° | 14.4° | 45°刻みは0°、回転混入なし。中間角度は比が保てない |
| 新モデル・修正前（e40e5a3） | 358/360 | 89° | 44.7° | 配置の誤りによる |
| 新モデル・修正後 | 360/360 | 19° | 7.8° | 45°刻みは0°、回転混入なし |
| 新モデル・回避指令 | 220/360 | 10° | 3.6° | 範囲外は停止。MAINは45°刻みを送る |

斜め45°はM1/M3またはM2/M4の2輪だけを使うため、トルクは4方向より小さいと考えられます（実機未確認）。MAINと OpenMV は、線の近くでは同程度なら前後左右を優先します。

### 仕組み

- `出力` はPWMではなく速度要求（210＝最大）です。仮の表は比例（要求160→PWM160）で、実測値ではありません。
- 並進と旋回を合成し、**全輪共通の倍率**で正規化する。持続下限(160)未満になる車輪は、停止か持続下限の組合せから、方向誤差と不要な旋回が最小のものを選ぶ。方向誤差30°超は停止（回避指令は10°超で停止し、旋回を混ぜない）。
- 持続下限が160のため、比を保てるのは基本方向の約±7°と45°刻みの近くだけです。下限を実測して下げられれば誤差は減ります。
- 始動：停止状態から100msで直線的に立ち上げ（10ms刻み、同時に始める車輪は同じ割合）、続けて `startDuty`(180) を60ms、その後は運転PWM。立ち上げ中だけ160未満になります。**回避指令は立ち上げを省きます。** 回り続けている車輪には立ち上げも始動補助もかけません。
- 逆転：4輪停止して200ms待つ。始動補助や立ち上げは迂回しない。
- 加速5/10ms、減速10/10ms。停止指令と通信断（100ms）は即時停止で、減速ランプは使いません（停止距離を伸ばさないため）。
- ブレーキ（両入力255）は初期値0＝使いません。`Drive::brakeMs` で停止指令の後に最大100ms。始動で解除し、逆転待ちは変えません。電流・発熱を確認するまで有効にしないでください。
- 初期設定（旧ミキサー）は、車輪の対応だけを修正しました。立ち上げは以前と同じ（停止から160をすぐ出力）で、テストコードの100ms立ち上げとは異なります。

### 実機で必ず測る仮値（`kWheels`、並びは M3, M2, M1, M4）

車輪ごと・IN1/IN2側ごと：`startDuty` 180、`holdDuty` 160、`gainPermille` 1000、`table` {160:762, 185:881, 210:1000}。**M1とM4の `forward` は表の `−` 方向**です。車輪ごと：`maxDuty` 210、`accelStep`、`decelStep`、`boostMs`。共通：`kStartRampMs` 100。

## 5. 白線回避

- 通信v1：停止条件を修正（上の表）。8方向は従来どおり。
- 通信v2（`competition_vision.py` の `LineGuard`）：16方向マスク（退避方位は45°の倍数のみ）、複数の線の同時処理、コーナーの斜め退避、`LINE_BLOCK_CM`(35cm)で接近方向を早めに閉じる、`LINE_CLEARANCE_CM`(25cm)で退避、解除は+5cmかつ2フレーム、退避方向の維持。退避先がなければマスク0＝停止。
- MAINはマスクが全開でない場合、前後左右・斜め45°の開いた方向だけを選び、avoid指令として送り、旋回補正を止めます。45°の倍数でない退避方位は拒否して停止します。
- 撮像からゴール・ボール認識までで100msを超えたフレームは「遅延」として送り、MAINは直前の正常な白線データを最大150msだけ使います（低速・avoid扱い）。床が認識できないフレームは直ちに停止します。
- 白線の更新を優先し、間に合わないゴール・ボール認識は飛ばします（最長20フレームで1回は実行）。
- 床の認識判定は、緑床が見える方向と白線が見える方向の合計が12以上です（以前は緑床だけで、線に囲まれた角で停止していました）。
- 床の欠けが1本だけの方向の扱いは8章のとおりです。
- 方向の幅（±30°）は機体幅の確認のため狭めていません。旋回して退避路を作る動作は、位置と旋回量を実測していないため未実装です。
- 希望方向が閉じている場合、開いた45°の倍数の中から、希望との角度差・逆転待ち（+40）・最寄りの線への近さで選びます。後退も含みます。
- 回避後のボール再捕捉は、通常の追跡状態に戻ることで行います。

回避距離の決め方（自動計算はしません。測って設定します）：

`回避距離(ミラー軸から) ≥ カメラから機体端まで ＋ 速度×(画像処理＋通信＋制御の遅れ) ＋ 停止距離 ＋ 速度×逆転待ち0.2s ＋ 余裕`

逆転待ちの間は停止（惰性）なので、余裕は大きめにします。

## 6. IR（ボール検出はIRだけ。`ir/ir_logic.h`、ポーリング命令 `0x02`）

**カメラはボールを検出も送信もしません。** MAINのボール情報はIRだけで、カメラで代替しません。

1. サンプル数で正規化（‰）し、センサー別ゲイン `kGain` を掛ける（初期値は全て1000＝未校正）。
2. 固着・断線センサーは約3秒で除外して両隣の平均で補う。8個以上が同時に飽和したら全体の異常として強度0・異常ビット全部を返す。
3. ピークの20%未満を雑音として除き、**隣り合って反応するまとまり**に分ける（孤立した無反応1個は橋渡し）。最も強いまとまり（直前方位の30°以内を1.3倍優先）の中でベクトル合成し、センサー間の角度を補間する。離れた反射は方位に混ぜない。
4. 信頼度はまとまりの集中度×受光レベル。2番目のまとまりが最大の半分を超えると下げ、同程度なら0に近づく。
5. 変化が大きいほど追従を速める円周フィルター。MAIN側で45°超の急変は2回一致で採用し、短時間予測・探索・再捕捉を行う（9章）。

| 状態 | MAINの動作と表示 |
|---|---|
| ボール未検出（通信正常） | 予測→探索。`no ball detected: searching` |
| IR通信断（100ms） | 停止。`IR link lost` |
| 異常センサーが4個以上 | 停止。`IR sensors failed` |

**限界**：全センサーが無反応になる故障は「ボールなし」と区別できません。受光の反射が直接光より強い場合は反射を追います。IR強度は距離に使いません（未校正のため、遠近による戦術の切替も削除しました）。

従来の命令 `0x01`（初期設定）の処理は変えていません。`kGain`、`kReflectionRatio`、`kFullLevel` は実機で調整します（2026年の公式ボールは42mm）。USBの `v` で12個の値と信頼度・異常ビットを表示します。

## 7. 姿勢制御（BNO055故障時を含む）

| モード | 条件 | 動作 |
|---|---|---|
| `VISION_ONLY`（主運用） | 両ゴールからの推定が、30°以内で5回連続 | 半分のゲインで攻撃方向を向く |
| `VISION_ONLY`（ゴール相対） | ゴール1つだけ | 位置合わせ・攻撃中のみ、半分のゲインでゴールを向く。方位は作らない |
| `BNO_ONLY` | BNO正常、視覚推定なし | **基準合わせ済みの場合だけ**補正 |
| `FUSED` | 両方正常 | 相補フィルター（差が30°以内のときだけ1回1%で視覚へ） |
| `DEGRADED` | どちらもなし | 旋回補正ゼロで走行継続 |

- 視覚の方位は「相手ゴール方向ベクトル − 自陣ゴール方向ベクトル」による**近似**です。コートの中心軸上以外では誤差があります。両ゴールを直近300ms以内に検出した場合だけ送ります。**ゴール1つの方位変化は回転角として扱いません。**
- BNO（GPIO4/5、0x28）：`delay` なしで接続確認→IMUPLUS→20ms読出し。無応答時は1秒に1回、最大5msのI2C待ち。ジャイロ校正3のときだけ使用。10回正常で採用、3回異常か200ms更新なしで解除。800°/sを超える段差は一度解除して取り直す。
- **BNOの基準**：視覚推定で合わせる。2秒以内の中断なら直前の推定を引き継ぐ。それ以外は「基準なし」となり、旋回にも攻撃方向にも使いません（ボール追跡の回転補正のみ）。電源投入時の向きを攻撃方向とみなすのは `bnoPowerOnReference = true` の場合だけです。**BNOだけで姿勢保持するにはこの設定が必要です。**
- 視覚とBNOの差が30°を超える状態が0.5秒続くと不一致となり、**旋回補正と方位による攻撃方向を停止**します。視覚が途切れても解除しません。BNOの取り直しか、一致の継続で解除します。
- DEGRADEDの「MOTOR通信が正常」は、MOTOR→MAINの返信がないため確認できません（MOTOR側の100ms停止に頼ります）。

仮値（配置からは+1が時計回り）：`turnSign`（**浮かせて向き確認が必須**）、Kp 0.5、Kd 0.05、不感帯10°/解除5°、旋回8〜30。

## 8. カメラ認識（ゴール・白線・床。ボールは扱わない）

### ゴール候補の判定（`goal_candidate`）

LAB色の領域ごとに次を確認し、**面積最大だけでは選びません**。

| 条件 | 初期値（未調整） |
|---|---|
| 画素数、ミラーの内外リング内 | `*_MIN_PIXELS` |
| ミラー中心から見た角度幅 | 6〜150° |
| 弧の長さ÷半径方向の高さ（縦長を除外） | 0.8以上 |
| 外接矩形に占める色の密度 | 0.2以上 |
| 外側（中心から遠い側）に緑床が続く → **除外**（床の上の機体・ボール） | 3点中2点 |
| 内側に緑床も白線も見えない → 品質0.6倍 | |

時間方向：3回の連続で信頼度が上がり、初回は40未満で使いません。45°を超える急な移動は2回続くまで採用せず、旧方位の信頼度を下げます。青と黄が90°未満なら弱い方を0、強い方を半分にします。姿勢推定は両ゴールが300ms以内に見え、100°以上離れる場合だけです。片方だけの場合は方位を作らず、MAINは半分のゲインでゴールを向くだけです。

**限界**：床より外側に緑が見えない位置の同色物体（コート外の物、リング端の機体）は除外できないことがあります。

### 白線

緑床から白に変わる点を境界とし、次のどれかで「白線と確認」します：白の幅が8cm以内で先に緑が続く／同じ方向か隣の方向に2フレーム続く。未確認の白も**その方向は閉じます**が、退避は始めません（1フレームの反射で急に動かないため）。白い機体でも2フレーム続けば白線と同じに扱います（安全側）。床の欠けが15°1本だけで、両隣2本ずつが見え近い線がない場合は開きます（`FILL_SINGLE_GAP`、近くの小物体の陰。未確認の仮定）。

## 9. ボール予測と消失時（`ROBOT_UPGRADE 1`、IRのみ）

α-βフィルターで方位と角速度を推定し、80ms先（最大15°）を狙う。BNOがある場合は機体の回転分を補正。

`TRACK`（100ms以内）→ `PREDICT`（信頼度に応じ約0.1〜0.3s）→ `SEARCH` → `REACQUIRE`（再発見から0.1s。追跡するが `ATTACK` はしない）→ `TRACK`

- `SEARCH`：最後の方位から始め、45°ずつ向きを変える八角形の移動を、0.4sごと、速度要求160で続けます。45°刻みは逆転待ちが不要です（PCのループテストで停止0）。通信と観測が有効な間は期限なく続けます。白線マスクで方向を選び直し、自陣ゴールが近い（距離40cm未満または不明）場合はその方向を除きます。
- 起動後に一度もボールを検出していない場合は停止して待ちます（`WAIT`）。
- IR通信断、またはIRセンサー異常（4個以上）の場合は停止します。カメラでは代替しません。
- その場旋回による探索は採用していません。IRとカメラは全周を見ており、持続PWMでの旋回は速すぎる恐れがあるためです。
- 八角形の実際の大きさと移動のずれは**実機未検証**です。ライン以外に位置の制限はありません。

## 10. 戦術と速度

状態：`SEARCH` `APPROACH` `ORBIT` `ALIGN` `ATTACK` `RECOVER` `AVOID_LINE` `SAFE_STOP`

- 攻撃方向：攻撃ゴール → 自陣ゴールの反対 → 推定方位 → 直前1秒の記憶 → 不明。攻撃色は `TARGET_GOAL`。
- ボールとゴールの角度差が15°以内で `ATTACK`（再発見直後を除く）（30°を超えるまで継続）、45°未満で `ALIGN`、それ以上は `ORBIT`。距離が不明なら方位だけで回り込む。線に塞がれたら反対回り。
- `ATTACK` が3秒続くと0.4秒下がる。
- **攻撃方向が不明な場合は、ボールに近づかない接線方向へ回り込んでゴールを探します。**ボールへ直接向かう追跡は `blindTracking = true` の場合だけです。
- ゴールの記憶は1秒、基準のあるなしに関係なくBNOが有効なら回転を補正して3秒です。姿勢の不一致中は使いません。
- 自陣ゴールが見えていて（信頼度25以上、0.8秒以内）、ボールがその方向にある場合、押し込む方向を除いて選び直します。開いた方向がすべて危険な場合だけ停止します。
- 自陣ゴールの誤認識・攻撃色の設定違いでは、これらの対策は効きません。記憶を延ばした分、機体が衝突で回された直後は古い方向を使う恐れがあります。
- 設定は `main/main_logic.h` の `Config` です。
- 優先順位：通信異常 → 白線 → センサー → モーター実現性（MOTOR側） → 姿勢 → 追跡 → 戦術 → 速度。白線回避中は旋回補正ゼロ。
- 速度要求：低速137（MOTORで持続下限へ）、通常160、遠距離185、攻撃195、回避175。線の近く・低信頼・姿勢誤差45°超は低速。
- キッカーGPIO11はLOWのまま。

## 11. 通信

| 区間 | 内容 |
|---|---|
| OpenMV→MAIN v1 | 9600bps、8バイト、XOR（従来） |
| OpenMV→MAIN 拡張 | 115200bps、32バイト、`C5 5C` **版3**、長さ、連番、CRC16-CCITT。ボール情報なし |
| MAIN→IR | `A5 5A 01 FE`（従来）／`A5 5A 02 FD`（新） |
| IR→MAIN | `AA 角度2 強度2 55`（従来）／`AB 角度2 強度2 信頼度 異常2 CRC8 55`（新） |
| MAIN→MOTOR | 12バイトDRIVE（変更なし） |

版3の並び：`0-1` ヘッダー、`2` 版、`3` 長さ、`4` 連番、`5` フラグ（認識可／退避／攻撃が青／処理遅れ／攻撃色有効）、`6-7` 方向マスク、`8-9` 退避方位、`10-11` 線の方位、`12` 距離、`13` 線の数、`14-19` 黄（方位2・距離・信頼度・幅・経過10ms単位）、`20-25` 青、`26-27` 推定方位、`28` その信頼度、`29` 処理ms、`30-31` CRC。不明は角度 `0xFFFF`、値 `255`。`PROTOCOL = 2` はこの拡張形式を選ぶ設定値です。**カメラとMAINは同じコミットを使います**（版2の通信は受理せず停止します）。

名目の送信時間：v1 約8.3ms、拡張 約2.8ms、DRIVE 約1.0ms。PIO UARTの115200bpsは**実機未検証**です。版や速度が合わない場合、MAINは受理せず停止します。RS485の送受信切替、IR応答待ち中は送信しない仕組みは維持しています。

## 15. 初心者向け実機検査手順

### 通電前に必要な設定（仮値は実測値ではありません）

| 設定 | 場所 | 実機検査前の値 | 変える条件 |
|---|---|---|---|
| `ROBOT_UPGRADE` | MAIN・MOTOR | 0 | 段階2・3の確認後 |
| `PROTOCOL` | OpenMV | 1 | 段階3 |
| `kWheels` | `motor_logic.h` | 仮値 | 段階2の実測値に置き換える |
| `TARGET_GOAL` | OpenMV | 試合の攻撃色 | 毎ハーフ確認 |
| `GROUND_POINTS` | OpenMV | 実測 | 未実測なら床上走行しない |
| `LINE_CLEARANCE_CM`・`LINE_BLOCK_CM` | OpenMV | 25・35（仮） | 停止距離の実測後 |
| `turnSign` | `main_logic.h` | 1（未確認） | 浮かせて向きを確認 |
| `bnoPowerOnReference`・`blindTracking` | `main_logic.h` | false | 通常は変えない |

**MAINの `ROBOT_UPGRADE 1` は、必ずMOTORも1にしてから使います。** 旧MOTORでは低速指令137と小さな旋回がそのまま低PWMになり、モーターが回らない恐れがあります。MAINはこの組合せ違いを検出できません。

確認の順：①モーター電源を切って4基板の通信表示 → ②浮上・初期設定（段階1）→ ③浮上でモーター測定（段階2）→ ④床上でモーター測定（手を添える）→ ⑤初期設定のまま床上で白線停止距離 → ⑥MOTORだけON → ⑦カメラv2とMAINをON（浮上）→ ⑧床上。**前の段階が合格しなければ進みません。** モーター診断は `diag` 入力後0.2秒間は動作指令を受け付けません。

**毎回、車輪を浮かせ、すぐ電源を切れる状態で始めます。** 通信が戻ると自動で動きます。

### 段階1：初期設定（すべてOFF）
1. 4基板を書き込む。MAINのシリアル(115200)で `CAM=OK IR=OK` を確認。
2. ボールを前後左右に置き、回転方向を確認。
3. カメラを隠す・ケーブルを抜く・IRを止める → 停止。戻すと再開。
4. ボールを隠す → 約0.5秒で停止。
5. 白線を前後左右に見せ、退避方向を確認。MAINで `d` を送ると停止指令になり、`g` で再開。

### 段階2：モーター測定（MOTORのUSB）
`diag` で診断開始（MAINの指令は無視）。コマンドは最長1.5秒で自動停止します。

| コマンド | 内容 |
|---|---|
| `p M1 + 160` | M1（右前）を表の `+` 方向にPWM160で0.7秒。`p 0 f 160` はチャンネル指定 |
| `k M3 - 180 150 1500` | 0.1秒だけ180、その後150（持続の確認） |
| `m 30 160 0 1000` | 新モデルで方位30°へ移動（方向誤差を表示） |
| `m 0 0 20` / `m 0 0 -20` | 旋回（左右） |
| `m 90 160 15` | 移動しながら旋回 |
| `b 40` | 以後の診断移動の終了時に40msブレーキ（0で解除、最大100） |
| `s` / `exit` | 停止／終了 |

PWMは120,130,140,150,160,170,180,190,200の順。**回らなければ繰り返さず、通電を続けないこと。** 浮かせた状態と床上を別々に記録します。

最初に `p M1 + 160`〜`p M4 - 160` で表の回転方向を確認し、次に `m 0/90/180/270 160 0` で4方向、`m 45 160 0` などで斜め、最後に `m 0 0 20` で旋回が**時計回り**かを確認します。時計回りでなければ `turnSign = -1` にします。

| 車輪 | 向き | 浮上:始動 | 浮上:持続 | 床:始動 | 床:持続 | 160/185/210の速度 | 電流 | 発熱 | 電圧 | 停止距離 |
|---|---|---|---|---|---|---|---|---|---|---|
| 0〜3 | f / r | | | | | | | | | |

値を `kWheels` に入れ、極性・前後左右・斜め・中間角度・旋回・逆転待ち・USB以外の通信断停止を確認してから、`ROBOT_UPGRADE 1`（MOTORのみ）にします。MOTORの新モデルは旧MAINと組み合わせられます。

### 段階3：カメラと通信v2
1. 校正（[校正手順](OPENMV_CALIBRATION_JA.md)）。必要なら `GOAL_DISTANCE` を `((半径px, 距離cm), ...)` で測定。
2. `PROTOCOL = 2` とMAINの `ROBOT_UPGRADE 1`。新IRとMOTORが必要。
3. MAINの2行表示で、`cam` の値（ms）、`err`、`mask`、`mode`、`bno`、状態名と停止理由を確認。
4. 浮かせたまま、ゴールを左右に動かして旋回の向きを確認（逆なら `turnSign = -1`）。
5. 白線（直線・角・2本）、ゴールの誤認識、BNOの抜き差しを確認。
6. 床上は低い場所・手を添えた状態で、停止距離を測ってから `LINE_CLEARANCE_CM` と `LINE_BLOCK_CM` を決めます。

## 18. 継続走行化（70a23c8からの変更）

**以下は `ROBOT_UPGRADE 1` と `PROTOCOL 2` の動作です。初期設定（全OFF）の停止条件は変えていません**（ボール未検出500msで停止する動作も同じ）。新しい制御は実機検証前に初期設定にしないためです。

| 状況 | 変更前 | 変更後 |
|---|---|---|
| IR通信断 | 停止 | 停止（IR専用化により、カメラでの代替は廃止） |
| ボール消失 | 最長1.5s（自陣距離の校正がなければ即）後に停止 | 探索を継続 |
| 攻撃ゴール不明 | 停止 | ボールに近づかず位置調整 |
| ゴール一時消失 | 0.3s記憶 | 1s（BNOありは3s） |
| 自陣ゴール方向／回り込み不可 | 停止 | 安全な別方向 |
| 希望方向が線で閉鎖 | 90°以内になければ停止 | 開いた方向なら後退も含め選択 |
| 退避方位が45°の倍数でない・閉鎖 | 停止 | 開いた45°の倍数へ |
| 処理遅延の1フレーム | 停止 | 直前データを150msまで使用 |
| 線に囲まれ緑床が12方向未満 | 停止 | 白線の方向も観測として数える |
| 小物体が床を15°分だけ隠す | その方向を閉鎖 | 条件付きで開く |

### 停止が残る条件

| 場所 | 条件 | 理由 |
|---|---|---|
| MAIN | カメラ通信断・CRC不正の継続（200ms）、同じ連番の再送 | 白線情報がない |
| MAIN | 床認識不能／遅延が150msを超える | 白線情報がない |
| MAIN | 開いた方向がない、退避先がない | 安全方向がない |
| MAIN | IR断、IRセンサー4個以上異常 | ボール観測がない |
| MAIN | 開いた方向がすべて自陣ゴール方向またはボールへの接近 | 誤攻撃の防止 |
| MAIN | 起動後ボール未検出、USB `s`/`d` | 開始前の飛び出し防止・手動停止 |
| MOTOR | 指令100ms途絶、出力0、回避の方向誤差10°超 | 通信断・実現不能 |
| MOTOR | 逆転待ち200ms（自動再開） | ドライバー保護 |
| MOTOR | 診断中と終了後0.2s | 手動検査 |
| OpenMV | 校正不正、床12方向未満、退避先なし | 認識不能 |
| IR | 停止指令は出さない（検出なしは強度0を返す） | |

停止理由はMAINの表示（状態名の後の文字列）、MOTORの `MODEL stop=`、OpenMVの `V2 OK/SLOW/NOFLOOR`、IRの `v` 表示で区別します。**MOTORからMAINへの返信はないため、MOTOR側の停止はMAINで分かりません（未検証・未実装）。**

## 20. ボール検出のIR専用化後の検査手順（車輪を浮かせて）

1. カメラ：`camera_calibration.py` の `BALL*` 行を削除（残っていても使いません）。`competition_vision.py` も必ずコピーします（初期設定のゴール表示にも使います）。
2. 画面で両ゴールの枠を確認。オレンジ色の物・青や黄の部品を床に置き、枠が付かないことを確認。実際のゴールが除外される場合は `GOAL_MIN_*` を緩めます。
3. 白線（直線・角・端）と白い物体を見せ、`mask` の閉じ方と退避の始まりを確認。**白線の見逃しがないことを先に**確認します。
4. IR：ボールを12方向とその中間に置き、方位と信頼度を記録して `kGain` を調整。鏡や白い板で反射を作り、方位が引かれないことを確認。
5. ボールを隠す（探索に移る）、IRのRS485を抜く（`IR link lost` で停止）、カメラを抜く（停止）を確認。
6. 拡張構成では18章の停止条件のうち「IR断でカメラにボールがない」は「IR断」に変わりました。

## 19. 大会投入前の残存リスク

- すべて実機未検証。モーターの仮値が合わないと、始動しない・速すぎる・曲がる。
- 安全停止が増え、校正不足だと動かない。
- 全輪同時の逆転待ち200msで追跡と退避が遅れる。
- 低速にできないため、白線手前の惰性が大きい可能性。
- 白線がミラーの死角（約18cmより内側）に入ると検出できない。
- 視覚方位は近似。ゴール誤認識で攻撃方向を誤る可能性。
- 通信v2の処理負荷でフレームが100msを超えると停止する。
- 審判の合図に合わせた開始方法の確認が必要。
