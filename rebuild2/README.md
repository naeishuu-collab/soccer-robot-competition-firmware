# rebuild2 最小競技ファームウェア

基準: `soccer-competition-rebuild` の HEAD eb0bf215 と、その時点の未コミット変更を含む実ファイル。元は変更していません。隣の `rebuild2-source-backup.zip` にコピー前の内容を保存しています（.git は含まない）。

MAIN の通常動作は改良 PD 追尾です。起動時は `g` 不要で自動開始します。起動後最低3秒はゼロ出力し、カメラやセンサー通信の準備を待ちます。`s` は手動停止、停止後は `g` で再開要求し最低2秒待ちます。`i` は状態表示。自動開始はUSB接続を必要とせず、手動再開の待機中はUSB切断または `s` でキャンセルします。ボール未検出はゼロ出力で待ち、再検出で追尾します。

白線危険フラグまたは退避要求中の退避方法は、末尾の改修内容を参照してください。方位不明・横方向・安全方向不明の場合はゼロで待機し、白線解除後に追尾へ戻ります。距離不明のみ、ゴール未検出のみでは停止しません。カメラ・IR通信断、破損IR応答、カメラ未準備・観測期限切れはゼロ出力、復旧後に再開します。これらは停止ラッチではありません。元コードの手動停止、キッカー LOW、起動ゼロ、モータードライバの反転待機と100ms watchdog は維持しています。元コードに物理停止スイッチ入力は見当たらず、外部の物理安全装置は独立して使用してください。

ゴール補正とオウンゴール防止は下記の条件で動作します。経路計画、BNO、キッカー動作は使用しません。旧ドキュメント・旧試験はコピー元の仕様を記載しているため、このファイルを優先してください。`competition/tests/rebuild2.cpp` が新しい動作のホスト試験です。

ビルド: `powershell -ExecutionPolicy Bypass -File competition/scripts/compile.ps1`。MAIN=RP2350B、IR/MOTOR=RP2350A。カメラ側は `competition/openmv` を使用。書き込みは実行していません。

未検証: 組み合わせ実機の白線方向・退避方向、PWM、センサー通信、カメラの視野と照明、通信断・復旧、物理安全装置。カメラは近接検出と保持・安全方向判定を行うため、危険フラグがあり、角度や方向の根拠を得られない場合はゼロ待機します。旧ホスト試験は旧仕様を前提にしており新仕様の合否には使えません。

## 2026-11-28 カメラ遅延と退避の改修

- CRC・シーケンスが有効なカメラの通信期限は従来の200 ms。さらに撮影・白線処理時間 `FRAME_MS` と受信後経過時間の合計が200 ms未満の READY 観測のみ使用する。`FRAME_MS=255` は上限飽和のため無効。SLOW（100 ms超）でも観測が新しければ追尾し、追尾PWMを±140に制限する。観測の長時間欠落はゼロ出力、復帰後は自動再開。
- 白線危険中は現在の角度から反対の前後方向を優先し、角度が不明・横方向なら一意の ESCAPE_MASK を使用。両者が矛盾すればゼロ待機。マスクが空でも前後の角度があれば退避。距離は使わない。角度が欠落しかつマスクが一意でない場合は、同じ危険継続中に観測した直近の角度を撮影時から150 ms未満のみ使用し、解除時に履歴を消す。方向が不明ならゼロ出力。移動履歴だけでは白線を横切らないことを証明できないため使わない。
- OpenMV はゴール検索を通常200 ms間隔で実施し、処理が重い場合は400 msへ下げる。既存プロトコルv3、校正値と撮影設定は維持。白線角度の品質改善や実機処理時間の短縮はまだ測定されていない。
- 安全方向マスクが空のときの角度だけによる退避は、カメラの視野や反対側の障害を証明しない。実機で線・鏡・車輪方向と制動距離を確認すること。

## ゴール選択と補正

`competition/openmv/camera_calibration.py` の `ENABLE_GOAL_CORRECTION` を `True` にすると既存ゴール検索を約200 ms間隔で実行し、相手ゴールがボール正面±4度以内・品質70以上・推定鮮度300 ms未満のとき、MAIN が PWM に最大±20を加える。`False` は検索を行わず角度不明を送るため、対応する MAIN は従来のPD出力を使用する。設定変更はカメラ再起動後に反映。MAIN の初期攻撃色は BLUE、自陣は YELLOW。MAIN の USB に `b` を送ると BLUE、`y` を送ると YELLOW が攻撃色になり、自陣は常に反対色。再起動時は BLUE に戻る。同期する画像検索の実機最長時間は未測定。初期値は `True`。通信形式は従来どおり。

白線、停止、ボール消失、低品質、古い・不明なゴール、ボール追尾と逆向きの補正は従来の出力を使う。計算式は符号付きゴール角度÷3を±20に制限し、左PWMから引き右PWMへ加える。各輪の出力範囲と遅延時のPWM制限を維持する。

## オウンゴール防止（暫定・未実機校正）

追尾中、品質70以上・推定鮮度300 ms未満の自陣ゴールが正面±25°、ボールが正面±20°で、両角度の差が15°以下の場合、前進を止めて左右反対の±140 PWMでその場旋回する。旋回方向は自陣ゴールから離れる側を優先し、整合する有効な攻撃ゴール方向を利用する。自陣ゴールが正面ぴったりで攻撃方向も使えない場合は右回りを選ぶ。同じ危険が続く間は方向を保持し、条件解除時に解除する。白線退避・停止は優先し、ゴール情報欠落は通常の追尾処理に戻る。

角度は距離を含まないため、危険判定の誤検出や球を別方向へ押す可能性がある。旋回方向・PWM・反転待機およびゴール検索が白線通信周期へ与える影響は実機未確認。`ENABLE_GOAL_CORRECTION = False` で検索を無効化できる。
