# シリアルモード（未実機検証）

Arduino IDEで `main/main.ino` を通常ビルドするだけで利用できる。電源投入時は停止。白線、壁、人や段差のない管理区域で、外部動力遮断の担当者を置く。試験モードは白線と退避判定を無視するため、カメラは障害物や落下を防げない。最初はモーター動力を遮断して状態を確認し、次に車輪を浮かせて固定して試験する。PWM上限210は停止距離や移動方向の安全を保証しない。

## Arduino IDEのシリアルモニター

115200bpsでMAINに接続し、`i` でIR通信とボール検出を確認する。`p`（PD追尾）、`y`（黄色ゴール）、`b`（青色ゴール）を選ぶと停止状態になりPD状態がリセットされる。次の新しいIR応答を確認し、`g` を1回送ると `START_PENDING: 2000ms` が表示され、2秒間は停止する。待機中の `s` またはモード変更でキャンセルされ `START_CANCELLED` が表示される。2秒後、通信・ボール・経路など選択モードの開始条件を再確認し、動作可能なら `STARTED` と表示して駆動する。条件を満たさない場合は `START_CANCELLED` と表示して停止を維持し、再度 `g` が必要。駆動中は時間制限がない。`R` の送信は不要。`s` で停止、`i` で状態表示、`h` でヘルプを表示する。待機終了後は機体が動き出す。

USB切断、IR通信異常、ボール喪失で停止し、復旧後も自動再開しない。条件を再確認してから `g` を送る。PD追尾 `p` はカメラがなくても動作する。`y` / `b` は正常なカメラ通信が必要で、カメラ異常でも停止する。ゴールが映らない場合はPD追尾に戻る。試験モードはいずれも白線を走行条件に使用しない。

`c` は通常競技モードを選び停止する。`g` 後は既存の競技判定で動き、駆動時間に上限はない。`s` で停止する。MOTOR側の通信監視と反転保護は維持される。

黄色/青色ゴールは指定色の新鮮な方位だけ使用する。IRのボール方向が前方±30度のとき、既存PD出力に小さいゴール方向補正を加える。ボール保持、押し込みや得点の成功、キッカーは保証しない。方位の符号・出力と実際の移動方向は実機未検証。

任意のWindows補助ツール `python competition/scripts/trial_deadman.py COM5 p` （p/y/b）は、スペースを押したときに `g` を送り、2秒待機の後、最大1.8秒の駆動後またはキーを離したとき `s` を送る。PC側プログラムが停止すると停止指令を送れない場合があり、ファームウェア側に時間上限はない。pyserialが必要で、シリアルモニターとは同時に同じCOMポートを開けない。
